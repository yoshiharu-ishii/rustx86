# ADR-0013: F1c (ネイティブJIT) を凍結して削除する — 収支がリンク税を割った

- 状態: **決定** (2026-08-13 ユーザー決定: 凍結・タグ保全・コード削除・復帰条件つき)
- 日付: 2026-08-13

  [ADR-0009](0009-pgo-shelved.md) (同じ寝かせ方の前例)、[perf-log.md](../reference/perf-log.md)、

## 背景 — F1cはどこまで行ったか

関門プローブ (#84) → 骨格+背景焼き (#85) → TLBインライン (#86) → 語彙v2 (#87) →
jcc両側焼き (#88) → 入場診断 (#89) → 予算つき途中退出 (#90) まで完成。
決定性ゲート (JIT on/offで命令数もシリアルFNVもビット一致) を2カーネルで常時維持し、
bzImageフルでカバレッジ46%・**同一バイナリ相対 -9〜13%** に到達した。

その後の単価攻め3連投が全て空振りした:

| 手 | 結果 |
|---|---|
| d1 世代落ちヘッド再焼き | **負け** (旧4勝1敗1分、カバレッジ46.6→42.9%に低下) |
| d3 ブロック内レジスタ割付 | ワッシュ (3勝3敗)。決定性ゲート合格 |
| d4 cc遅延化 (6ストア→消費点) | ワッシュ (3勝3敗)。決定性ゲート合格 |

## 実測 — 判定を確定させた朝の冷間三つ巴 (2026-08-13、無負荷、交互3周)

| バイナリ | bzImageフル 970M | MIPS |
|---|---|---|
| **bootphase (coreだけ、craneliftリンクなし)** | **15.0〜15.3s** | **~64** |
| jboot off (cranelift同居、JIT不使用) | 18.6〜19.5s | ~51 |
| jboot on (JIT全開、カバレッジ46%) | 17.1〜18.5s | ~54 |

- **リンク税 +25%**: craneliftをリンクしただけでインタプリタ部が遅くなる
  (コードレイアウト、Mytkowicz 2009。perf-log 2026-08-12で発見済み)
- **JITの取り分 -5〜9%** はリンク税を埋められない —
  **JITを全部効かせても素のcoreバイナリより +19% 遅い**

## 収支分解 — なぜ「作りきって」も届かないか

JITの収支 = カバレッジ × 単価 − リンク税。

- **カバレッジ天井 46%**: 残りは冷コードの裾野 (無ブロック~90M)。ブート様WLの
  構造限界で、プレウォーミング禁止 (ADR-0012 決定4) の下では動かない
- **単価の伸びしろが細い**: d3/d4の空振りが示した通り、**B4+dcache後の
  インタプリタから、ヘルパ呼び形のテンプレJITが削れる直列仕事はもう薄い**。
  生成コードもTLB照合→ロード→演算→ストアという同じ依存連鎖を歩いている。
  ブログの分水嶺で言えば、構想は「仕事を減らす」(連鎖を畳む) だったが、
  実装の現在地は「並べ替え」に落ちた — そして並べ替えのために足した機構
  (craneliftリンク) が+25%の実コストになった。B3・B5と同じ敗因構造
- 楽観シナリオ (単価が今から半分) でも 0.54 + 0.46×0.5 ≈ **相対-23%** で
  リンク税と相殺止まり。**bzImageフル土俵で100 MIPSにJITで届く道は現構造に無い**
- 効きは展開ステブ (狭くて熱い) に偏る実測 (9.7→8.3s、カーネル本体8.8→8.5s、
  タグ exp/f1c-d2-jboot-phases) もこの分解と整合する

## 議論の記録

**続行論 (やめない理由になるか):**

- 北極星v86の実測160〜185 MIPSはJITで出ている。ただしそれは「連鎖を削る」深さ
  (ホストフラグ流用・ブロック跨ぎのレジスタ常駐・トレース化) と、ブートではない
  定常WLでの話。到達には週単位の投資が要り、それでもこの土俵の
  カバレッジ天井46%が上限を縛る — 続行の論拠にならないと判断

**凍結論 (決め手):**

- 単価攻め3連続空振りは偶然ではなく構造 (上の収支分解)
- 凍結はゼロ維持費: フロントエンド資産 (脱出モデル・語彙・カバレッジ機構・
  決定性の審判) は設計として残り、実装はタグで完全保全
- 100 MIPSへの寄与見込みが無い機構を抱え続けるより、
  「仕事を減らす」羅針盤に開発を戻す

## 決定

1. **F1cを凍結し、mainからコードを削除する**。対象: jit-nativeクレート、
   coreの受け口 (JitHook・jit_try_*・collect・dcache Entryのjitフィールド・
   熱カウンタ)、wasm側JIT生成器 (ADR-0008で凍結済みのF1b)、JIT系CIゲート
2. **復活は `f1c-final` タグから** (revert一発)。実験d1〜d4は `exp/f1c-*` タグ
3. 削除で dcache Entry が痩せる — **「受け口の税」を削除前後の冷間A/Bで実測**して
   台帳に記録する (互換税の残り~6%を「I側の圧」と推測したままの宿題の検証を兼ねる)

## 復帰条件 (寝かせ = いつでも起こせる)

1. **土俵が定常WLに変わったとき** — DOSゲーム常駐・ポストブートの計算・
   Tier 8/9 (Firecracker的microVM) の長寿命ゲスト。ブートの冷コード裾野が消え、
   カバレッジ天井が外れて収支が反転し得る
2. **「連鎖を削るJIT」に投資する決断をしたとき** — ホストフラグ流用 (F3)・
   ブロック跨ぎレジスタ常駐・トレース化。B3 (ペア融合) が「生成コード内では
   前提が変わる」で寝ているのと同じ層の話で、起こすなら一式まとめて
3. **リンク税が消えるか、払う価値が出たとき** — 配布形態の変化、または
   絶対値の物差しがjboot系バイナリ側に移る運用

## 教訓

- **JITの収支は「カバレッジ × 単価 − リンク税」の3項で読む。** 相対A/B
  (on/off) だけ見ているとリンク税が見えない — 「別バイナリの絶対値は比べるな」
  (pitfall 6) の裏返しで、**物差しの一本化こそが逆ザヤを可視化した**
- インタプリタを先に磨き切る (B4+dcache) と、テンプレJITの旨味は先食いされる。
  JITをやるなら「インタプリタが構造的に払えないコスト」(依存連鎖) を
  削る深さまで一気に行くか、行かないか — 中間深度に長居しない
