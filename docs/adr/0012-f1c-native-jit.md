# ADR-0012: F1c-a — ネイティブJIT (Cranelift) の骨格と背景焼き

日付: 2026-08-12
状態: 採用
関連: [ADR-0008](0008-template-jit.md) (テンプレートJITの設計とF系ロードマップ、
関門プローブの追記)、[ADR-0009](0009-pgo-shelved.md) (運用判断を持ち込まない)、
[ADR-0011](0011-tier-redraw-after-compat.md) (F1c前倒しの経緯)

## 何を決めるか

関門プローブ (ADR-0008追記、2026-08-12) が「回収可能、ただし焼きが重い」と
出した。F1c-a = ネイティブ (Cranelift) バックエンドの骨格の設計を決める。

## 決定

### 1. ランナーは `jit-native` クレート — coreの無依存は不変

Craneliftを背負うのは新クレート `jit-native` (ワークスペースメンバ)。
coreとの境界は**F1aで敷いた口をそのまま使う**:

```
core (無依存)                          jit-native (Cranelift)
  jit::collect_run  ── JitBlock ──▶  translate (CLIF生成)
  jit::layout       ── 実番地表 ──▶  定数として焼き込み
  dcache.drain_hot  ── 熱い頭 ───▶  焼きキュー
  dcache.set_jit    ◀── 据え付け ──  焼き上がり
  JitHook.enter     ◀── 実行 ─────  テーブル直呼び
```

wasm生成器 (wasm/src/jit.rs) と**同じ意味論契約**をCLIFで写す:
- フラグは lazy flags の材料 (cc_*) をメモリへ書くだけ。評価器は二重実装
  しない (CF/条件はヘルパ呼び)
- メモリ・スタック形はヘルパ (core の `jit_try_*`) — フォールトしそうなら
  **状態を1つも変えずに脱出**、返り値=完全実行数、core側がやり直す
- ipはブロック出口で1回。tsc/tickの清算はcore側 (契約は増分3のまま)
- 語彙は現行F1b全量 (mov/ALU/lea/ロード/ストア/RMW/スタック形/jcc/jmp/call/ret)

### 2. 焼きは背景スレッド — できた物から差し替える

関門プローブの数字 (焼き53〜276µs/ブロック、熱い頭~31k = 前払い~2.2s) から、
**焼きを実行の裏に隠す**のがネイティブ側の設計要件:

- メインスレッド: `pump()` で drain_hot → collect_run (要 &Machine) →
  ブロック列を焼きキューへ送る。**送ったら待たない**
- 焼きスレッド (1本): Craneliftでコンパイルして完成品 (関数ポインタ) を返す
- メインスレッド: スライス境界で完成品を回収し、**collect時のページ世代と
  照合してから** set_jit で据え付ける (世代が動いていたら捨てる —
  自己書き換えとの競合をここで閉じる)

### 3. 決定性: 据え付け時期はゲスト状態に影響しない (証明の形)

焼き上がりの時期はスレッドスケジューリング依存で毎回変わる。それでも
ゲストは決定的である — 根拠は**案A (毎命令の受付点、ADR-0008)**:
JITブロックはインタプリタと完全に同じ状態遷移を刻み、割り込み受付・tick・
清算の位置も同一なので、「どの命令からJITで走ったか」はゲストから観測できない。
据え付けが1スライス遅れても実行結果はビット同一。

見張りは従来と同じ2段:
- **jit-check相当のネイティブゲート**: interp と JIT で起動の命令数と
  シリアル全文が一致すること (jbootに内蔵、CIへ)
- 食い違ったら interp/JIT並走の save_state バイト比較二分審判 (F1b-1で確立)

### 4. プレウォーミングの禁止 (ユーザー指示 2026-08-12)

- **コードキャッシュを永続化しない** (焼いた物を保存して次回起動で読む、を
  しない)。熱は毎回、実行の中で自然に載る
- **計測に温め走行を入れない**。交互A/Bは常に冷間起動から
- 理由は [[no-operational-tuning]] と同じ — 「訓練済みなら速い」は
  運用判断を開発に持ち込む。スナップショット起動 (ゲスト状態の保存) は
  別物で従来どおり (あれはゲストの機能でありJITの温めではない)

## やらないこと (F1c-aの外)

- TLBヒット経路のインライン化・検査の畳み込み (F1c-b — 単価の本丸)
- ブロック連結・トレース (F1c-c)
- opt_levelの調整 (プローブでnone/speed同値 — speed固定)
- wasm側の凍結解除 (F1cの数字を見てから、ADR-0011台帳)
