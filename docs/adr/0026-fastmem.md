# 0026: fastmem — ホストMMUでゲストメモリを写像する (F2)

日付: 2026-08-18 / 状態: 採用 (ユーザー裁定「互換を壊さないなら」) / 関係: [jit-roadmap3](../reference/jit-roadmap3.md), [0020](0020-external-review-round3.md), [0025](0025-tick-256.md)

## 背景

第3ラウンド調査の結論。メモリアクセスは最頻出テンプレートで、TLBインライン
ヒットでも~29ホスト命令、ストアは全部ヘルパ呼び。ゲスト空間をホストの
仮想メモリに写像すれば `base+addr` の1-2命令になる — Dolphinが**ページング
有効ゲストでも成立**させて全体2倍を実証済み (PR #13768)。唯一の2倍級鉱脈。

## 互換の契約 (これが採用条件)

1. **ゲスト可視の意味論は1bitも変えない**。fastmemは実行経路の最適化で、
   命令数・割り込み位置・フラグ・メモリ内容の可視遷移は不変。裁定者は
   既設の門番 (jboot/jcmd指紋・smc系・cosim・gcc-check)
2. **opt-in**: `RUSTX86_FASTMEM=1` で有効、既定off。offなら現行経路そのもの
3. **非対応環境では自動off**: wasm (シグナル無し)・未実装OSでは土台ごと
   組み込まれない (cfg) か実行時にoff。coreの公開APIは変えない
   (`Machine::mem` は `Deref<Target=[u8]>` を保つ)

## 移植性

| ホスト | 成立 | 手段 |
|---|---|---|
| macOS arm64 (現行定規) | ○ | mmap + SIGSEGV/**SIGBUS両方** + mach系。**ホストページ16KiB** — 4KiBゲストページのミラーは物理連続×4整列のときだけ合成 (Dolphinと同条件)。カバレッジが部分的になるリスクは実測で裁く |
| Linux / WSL2 (x86_64/aarch64) | ○ (**むしろ有利**) | memfd_create + mmap + SIGSEGV。ホスト4KiBページで完全粒度のミラー |
| Windows ネイティブ | 将来 | VirtualAlloc2 placeholder + ベクタ化例外 (yuzu先例)。初版スコープ外 — 自動offで互換維持 |
| wasm | 対象外 | シグナル無し。ソフトTLB路線を維持 (これが「両ビルドで意味論同一」の担保でもある) |

## 設計の要

### RAMの置き場: GuestRam抽象

ミラー (同一物理ページの多重仮想写像) を張るには、RAMが共有可能な
バッキング (memfd / mach entry) である必要がある — `Vec<u8>` では張れない。
`Machine::mem` を `GuestRam` (Deref/DerefMut<Target=[u8]>) に差し替える:

- wasm/未対応: 中身はVec (現行と同一)
- native+fastmem: 4GiBのPROT_NONE予約の中に、RAM実体 (memfd) を物理配置どおり
  マップ。MMIO/VRAM窓/空洞はPROT_NONEのまま = 触るとフォルト

### SMC検出との両立 (最重要の設計問題)

自己書き換え検出はストア経路の `note_write` が担う (ADR-0020)。fastmem
ストアはRustを通らないので、**保護で同じ意味を作る**:

- `page_has_code` が立つページは、fastmemの**ストア用写像を書込禁止**にする
  (mark_code_page = mprotect RO も兼務)
- コードページへのストアはフォルト → 従来経路 (note_write込み) へ →
  世代が進んでページの写しが捨てられたら書込可へ戻す
- つまり「ビットを見る」を「ページ保護」に写しただけで、検出の意味論は同一。
  再発防止は smc系テストがそのまま見張る (fastmem on で全部走らせる)

VRAM窓 (dirtyフラグ) も同じ形: 書込禁止写像+フォルトでdirty→従来経路。

### ページング対応 (第2段の本丸)

ゲスト線形→ホストの**線形ミラー**をmmapで構築 (Dolphin式):

- ページテーブル歩きの結果 (TLB fillと同じ情報) で、線形4KiBページ→RAM実体
  のオフセットへMAP_FIXEDの再写像。**遅延構築** — フォルトした線形ページ
  だけ張る
- 無効化フックは既存のTLBフラッシュ点そのもの (invlpg / mov CR3 / CR0.PG /
  ページ保護変化)。全捨てでなく差分で剥がす
- **Dirtyビットの罠**: A/D未設定ページを先に張ると、ビット更新が起きない。
  ストア用写像は「D=1で変換済み」のページだけ張る (読み用と書き用で
  写像を分ける — Dolphinの定石)
- 「TLBが事実上無限大」問題: invlpgせずPTEを直接書き換えるゲストには嘘を
  つくが、それは実機のTLBでも非アーキテクチャ的動作。ソフトTLB側と挙動を
  揃える (ソフトTLBのフラッシュ点=ミラーの剥がし点)

### シグナルハンドラの規律

- SIGSEGV/SIGBUS両フック。fastmem領域外のフォルトは**即座に旧ハンドラへ
  転送** (Rustのスタックガード等を壊さない)
- ハンドラは同一スレッドで走る — pthread_jit_write_protect_np (per-thread)
  はハンドラ内でトグル可 (Dolphin実証)。書込モードのままの脱出禁止 (RAII)
- 初版のフォルト処理は「遅延写像の構築」と「従来経路への退避」のみ。
  JITコードのバックパッチ (フォルト点をslow呼びに書換) は第3段

## 段階計画 (各段で全ゲート緑が合格条件)

1. **土台 (挙動不変)**: GuestRam抽象 (wasm=Vec / native=memfd+4GiB予約)、
   シグナル基盤 (登録・転送のみ)、RUSTX86_FASTMEMフラグ。目安: 半日
2. **線形ミラー**: 遅延構築・フラッシュ点フック・Dirty遅延・SMC/VRAM保護。
   まずインタプリタの読み書き速い道から使う (translate_forの手前)。1〜2日
3. **JITテンプレートの直アクセス化**: emit_loadのTLBインライン路をミラー
   1-2命令に置換、ストアもインライン化。フォルト時バックパッチ。1〜2日
4. 判定: 全定規 (jboot/jcmd/ディスク課程) 交互A/B + Linux (WSL2) でも実測。半日

効果が16KiBページ制約で出なければ**chaining同様「作って測って台帳へ」**
(その場合もLinuxホストでは効く可能性が高いので、定規を分けて裁く)。

## 棄却・保留

- Windowsネイティブバックエンド: 初版スコープ外 (自動off)
- インタプリタのstep経路への適用: 速い道 (fast_read/write系) だけで十分 —
  遅い道は正しさの原本として温存
- ゲストRAM>4GiB (PAE): 対象ゲストが32bitなので不要

## 追記 (2026-08-18、段2+PGE実測後の裁定): 段2は不採用・寝かせ

段2 (線形ミラー、有効表方式) とPGE (CPUID bit13広告+G保持) まで実装して
測った。**正しさは全部緑** — 指紋はfastmem×JITの4通りで一致 (PGE込みの
新基線 jboot=aa18…/jcmd=f2bd…)、204テスト緑、G群はmov cr3を設計どおり
生き延びた (ブート66群・gcc課程4,274群が全てG)。

**性能は赤で不採用**: gcc窓-1〜2%、ブート+2% (交互3周)。原因の連鎖 —

1. **検査の前置き (~12命令) を全ロードが払う**のに、ヒットが足りない。
   ユーザー空間 (cc1、窓の主役) はGにならず、macOSの16KiB制約 (物理連続×4)
   でミラー化がほぼ成立しない
2. カーネル側はG保持で温かいのに、ブートでも勝てない — 置き換えたTLB
   インライン路 (29命令) とミラー路 (~14命令) の差より、外れの前置きと
   mmap維持費 (張り9.5k・非G剥がし) が重い
3. 前置きを消すには**シグナル+バックパッチ** (検査なし直アクセス) まで
   行くしかないが、それはRust実行中のシグナル復帰を避けた設計判断
   (このADRのv1原則) と衝突する

**再訪の条件** (台帳): (a) Linuxホストが定規になったとき (4KiBページで
群制約消滅 — ユーザー裁定でWSL2計測は省略中)、(b) JIT生成コード限定の
シグナル+バックパッチ設計を受け入れるとき (Dolphin式、生成コードのみ
フォルト可能なら復帰は安全)、(c) レジスタ常駐化でロード雛形が痩せ、
前置きの相対コストが変わったとき。

実装はタグ **exp/fastmem-2** に寝かせる (PGE広告込み — mainには入れない
ので**指紋基線は現行のまま動かない**)。段1 (GuestRam抽象) はマージ済みの
まま無害 (既定はVec)。次の10%級はレジスタ/cc常駐化バンドル (jit-roadmap3)。
