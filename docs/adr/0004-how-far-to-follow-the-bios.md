# ADR-0004: BIOSにどこまで付き合うか

- ステータス: 採択 (2026-08-08)。実測の結果を「実際にやってみた」に追記
- 前提: [ADR-0002](0002-devices-and-16bit-unix.md)

## 背景

ELKSを起動させるまでに、BIOSの穴を5つ埋めた。A20ゲート、BIOSデータエリア、
PICの初期配置、INT 08h、INT 13h AH=03。どれも「実BIOSがやるはずの仕事」で、
抜けているとOSは必ずどこかで転んだ。

FreeDOSを載せようとすると、さらに要る。INT 16h (キーボード) は
「常にキー無し」では話にならず、INT 10h も画面のスクロールが要る。

ここで当然の不安が出る。**これはどこまで続くのか。** 相手を増やすたびに
BIOSを実装し続ける羽目になり、いつまでも本体に進めないのではないか。

## 分析: 需要が有界な相手と、無界な相手がいる

一括りにすると判断を誤る。**BIOSを呼ぶのが誰か**で性質が変わる。

| 相手 | BIOSの需要 | 有界か |
|---|---|---|
| ELKS | 小さい。8042もVRAMも直接触るため | ✅ 実装済み |
| FreeDOS本体 (起動〜`C:\>`) | あと数個 | ✅ 有界 |
| **DOSアプリケーション** | **際限がない** | ❌ |
| **32bit Linux** | **ほぼゼロ** | ✅ 構造上 |

### OS本体の需要は有界である

OSが起動に使うBIOSサービスは決まっている。画面に文字を出し、ディスクを読み、
キーを取り、メモリ量と装置構成を尋ねる。**OSは起動したら自前のドライバに
乗り換える**ので、そこから先はBIOSを呼ばなくなる。ELKSがまさにそうで、
起動後は8042とVRAMを直接叩いている。

### DOSアプリケーションの需要は無界である

DOSは「BIOSの上に薄く乗るだけ」の設計で、**アプリが直接BIOSやハードウェアを
叩くのが当たり前**だった。ゲームはVGAのレジスタを直接触り、TUIはINT 10hの
モードを切り替え、マウスはINT 33h、音はサウンドカードのポートを叩く。
アプリの数だけ要求がある。**ここには底がない。**

### Linuxの需要はほぼゼロ — 構造上そうなる

直感に反するが、**Linuxが一番安全**である。BIOSを呼ぶのはリアルモードの
setupコード (`arch/x86/boot/`) で、そこがINT 10hで早期のコンソールを出し、
INT 13hでカーネル本体を読み、INT 15h AH=E820でメモリマップを取る。

だが [ロードマップ Tier 4b](../../README.md#tier-4-linux起動--ここで完成) で選んだのは
**bzImage + initrd を直接ロードして32bitエントリへ飛ぶ方式** (QEMUの `-kernel` 相当)
である。これは**そのsetupコードを丸ごと飛ばす**。呼び出し側が居なくなるので、
BIOSサービスも要らない。メモリマップは `boot_params` に自分で書いて渡す。

そして32bitエントリに入った後のカーネルは、**BIOSを呼べない**。
プロテクトモードで自前のGDT/IDTを立てており、リアルモードのBIOSへ戻る道が
無いからである。装置はvirtio (I/Oポートとメモリ) で見えるので、BIOSは要らない。

## 決定

### 1. FreeDOSは「`C:\>` が出て内蔵コマンドが動く」までを目標にする

DOSアプリケーションは追わない。BIOSの穴埋めが無限に続くのは**アプリの側**で、
そこへ踏み込むと本体 (32bit Linux) に永久に着かない。

内蔵コマンド (`DIR` `VER` `TYPE` など) が動けば、**BIOS層が本当に正しいかの
検証**としては十分である。ELKSはBIOSをほとんど使わないので、この層は
今まで検証できていなかった。

### 2. Linuxには最後までBIOSを使わせない

Tier 4b の「BIOSは作らず bzImage を直接ロードする」を、単なる手間の節約
ではなく**BIOSの無限後退を断つための決定**として位置づけ直す。

APM/ACPI・VESAといったBIOS依存の機能は、カーネル設定で外すか使わない。

### 3. 未実装のBIOSサービスは、これまでどおり即panicする

黙って0を返すと、遥か後方で意味不明な暴走として現れる。panicは
`INT 10h AH=0x13 未実装` と**名前を教えてくれる**ので、埋めるのが安い。
ELKSのときも、詰まるたびに次にやることが1行で分かった。

**穴が有限だと分かっている相手に対しては、これが最も速い進め方である。**

### 4. FreeDOSカーネルは8086ビルドが要る。無ければ32bit化の後に回す

FreeDOSの標準配布は386以降向けにビルドされていることが多い。
現在のCPUは8086+186なので、そのままでは読み込めない可能性がある。
8086ビルドが手に入らなければ**Tier 3 (32bit化) の後に回す** —
FreeDOSは寄り道であって、そのためにCPUの順序を変えない。

## 結果

### 得られるもの

- **BIOS層が検証される**。ELKSはBIOSをほとんど使わないので、
  INT 16h も INT 10h のスクロールも「書いたが誰も呼んでいない」状態だった
- 相手ごとに需要の性質が違うと分かったので、**どこで止めるかを先に決められる**
- Linuxへの道にBIOSの不確実性が無いことがはっきりした

### 代償

- FreeDOSのために足したBIOSサービスのうち、Linuxで使うものは**無い**。
  ここは丸ごと寄り道である。ELKSの `INT 13h` HLE と同じ位置づけで、
  「安いが捨てになる」ことを承知で足す
- `C:\>` で止めると決めても、そこに至るまでに何個要るかは開けてみないと
  分からない。**上限を決めて、超えたら引き返す**のが正しい (10個を目安とする)

## 実際にやってみた (2026-08-08)

FreeDOS 1.4 Floppy Edition の 8086ビルド (`144m/x86BOOT.img`) を起動した。
懸念していた「8086ビルドが無いのでは」は杞憂で、**フロッピーには `KERNEL.SYS` (8086) と
`KERNL386.SYS` (386) の両方が入っていた**。

### 結果: BIOSの穴は5個で足りた。**止まったのはBIOSではなくCPUだった**

| 足したもの | 中身 |
|---|---|
| `INT 1Ah AH=02/04` | RTCから時刻と日付を読む。CMOSを時計として動かした |
| `INT 1Ah AH=01/03/05` | ティックとRTCの書き戻し (DOSは起動時にRTCを読んでティックへ写す) |
| `INT 13h AH=41` | LBA拡張の有無。**無いと正直に答える** (フロッピーにEDDは無い) |
| `INT 10h AH=11` | フォント情報。DOSはここから**画面の行数**を知る |
| `INT 10h AH=02/03` | カーソルの移動と取得。**空実装だった** |

上限に決めた10個の**半分で済んだ**。OS本体の需要が有界だという読みは正しかった。

到達点は **FreeCOM (COMMAND.COM) が起動し、ウェルカム画面のロゴが出るところ**まで。
その先で `unimplemented opcode 0x66` で止まった。命令列はこうなっている。

```
53                  PUSH BX
66 9C               PUSHFD                  ← 32bitオペランドサイズ・プレフィクス
66 58               POP EAX
66 0D 00 00 04 00   OR EAX, 0x00040000      ← bit18 = AC フラグ
```

**386と486を見分ける定番のCPU判定**である。カーネルは8086ビルドでも、
起動の途中で走るユーティリティは386命令を使っていた。

### 決定の修正

**FreeDOSの続きは Tier 3b (32bitオペランドサイズ・プレフィクス) の後に回す。**

「8086ビルドが手に入らなければ 32bit化 の後に回す」と決めていたが、
理由が変わっただけで結論は同じになった。**ビルドはあったが、周辺のツールが386だった。**
ここで `0x66` を部分的に実装するのは Tier 3 の仕事を順序を崩して雑にやることなので、
やらない。

### 副産物: BIOS層の穴が2つ見つかった

これがADR-0004で一番期待していた効果である。ELKSはBIOSをほとんど使わないので、
この層は「書いたが誰も呼んでいない」状態だった。

- **`INT 10h AH=0E` (テレタイプ) がテキストVRAMに書いていなかった。**
  診断用の文字列へ積むだけだったので、BIOS越しに描くOSの画面が
  **ブラウザに一切出ない**状態だった。ELKSがVRAMを直接叩くOSだったため露見しなかった
- **`INT 10h AH=02` (カーソル移動) が空だった。** DOSの画面は
  「カーソルを動かして書く」の組で作られるので、これが無いと何も出ない

さらに表示経路の穴も1つ。**コードページ437の表が無かった。**
FreeDOSのロゴは `0xDB` (█) の羅列で描かれているが、確認用の関数も
ブラウザの描画もASCII以外を捨てていたため、**出ているのに画面が空に見えた**。
表を `core` に置き、CLIとブラウザで同じものを使うようにした。

## 検討した代替案

**FreeDOSを完全に飛ばす**: ADR-0002 の判断がこれだった。ただし当時の理由
「INT 21h のDOSサービス群が捨て仕事になる」は、**本物のFreeDOSを載せるなら
当てはまらない** — FreeDOSは自分でINT 21hを持ってくる。理由が消えたので、
判断をやり直す価値があった。

**DOSアプリまで動かす**: 面白いが底が無い。VGAのプレーナモード、サウンドカード、
INT 33hのマウス…と広がり、32bit Linuxに永久に着かない。
やるなら Tier 4 (Linux) に到達した後の横展開とする。

**BIOSを本物のROMで動かす**: SeaBIOSなどを載せれば穴埋めは終わる。だが
「BIOSが何をしているか」を自分で書くのがこの教材の目的なので、
ブラックボックスを1つ増やすことになる。
[ADR-0001](0001-16bit-cpu-and-cosim.md) の「BIOSは実装せず必要なサービスだけHLEする」
を維持する。
