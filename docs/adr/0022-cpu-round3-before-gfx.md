## 背景

Part 2の実測 (ADR-0020/0021) でインタプリタの土俵は使い切った: C11 (-19%、
105 MIPS温間) が最後の大物で、残る案は全部「OoOの影」(3連続実証) か
「観測粒度の箱」(C10/C14) に入っている。**単発の数%はもう出ない。**

一方、次のTier 6h (ReactOS、Pentium 200MHz級 = 150〜200 MIPS) と Tier 8
(マイクロVM) は今の105 MIPSでは足りない。広範囲調査 (2026-08-16、4系統) で、
F1cを殺した2つの壁が両方崩せることが分かったので、**グラフィックス (Tier 6)
の前にCPU第3ラウンドを差し込む**。

## 調査の要点 (裁定の根拠)

1. **リンク税なしのJITバックエンドは実在する。** 手書きAArch64テンプレート
   エミッタの相場は DOSBox dynrec = 1,220行 / blink = 2,343行 — 40uop語彙なら
   1,000〜2,000行・2〜4週間。dynasmrt併用でもランタイム4.5k SLoC・依存3つ・
   数十kB (Craneliftの2桁下)。macOSのW^X (MAP_JIT +
   pthread_jit_write_protect_np) はmprotectより安い (CPython実測+1.4%)。
   copy-and-patch (CPython 3.13方式) は税最小クラスだがuop意味論をCで二重管理
   することになり「意味論の原本は1つ」に反するため次点
2. **ブロック粒度化しても命令数決定性は守れる。** QEMU icountの手法 —
   タイマ満了の直前でブロックを切り直す — で、割り込み配送の**命令番号を
   毎命令モードと完全一致**させられる (基準値の引き直し不要)。守る規則:
   STI/POPF/IRET/MOV SSは強制ブロック終端 (SDMのSTI shadow)、時計読み出し
   (RDTSC/PIT) はブロック内の命令位置で補間 (Dolphinが怠って壊し、JITブロック
   粒度化で直した実例 PR #3601)。「正確モード=検証 / 高速モード=運用」の
   二段構えはQEMU (icount) / Dolphin (dual core) の業界定石で、新しい門番
   **「正確モードvs高速モードのクロスチェック」**が既存の門番思想の延長に立つ
3. **爆風半径は契約側にある。** ブロック粒度化のcore実装は~100行
   (step_cachedの脱出3条件と帳簿) だが、cosim (毎命令EFLAGS)・lockstep
   (Unicorn count=1)・regress基準値という契約の再設計で計1〜2週間。
   **インタプリタ単体で開ける価値はない** (C5のtick一括化+10%悪化が実証) —
   JITブロック内のチェックポイント除去とC14 dead-flags解禁とセットでのみ黒字
4. **31cy/命令の内訳はこのM1で測れる。** `mperf` (sudoで包むだけ) と
   `darwin-kperf` crate (sudo必須・SIP無効化不要)。鍵イベント:
   MAP_DISPATCH_BUBBLE (フロントエンド税) / MAP_STALL (バックエンド詰まり) /
   BRANCH_MISPRED_NONSPEC (×~13cy)。M1にL2キャッシュミスイベントは無い。
   カウンタのmask制約により2〜3回に分けて測る (決定的実行なので合成できる)

## 決定 — CPU第3ラウンドの段取り (Tier 6の前)

| Stage | 中身 | 出口条件 |
|---|---|---|
| 0 | **診断とgcc第2定規** — kperfハーネス (sudo実行はユーザー)、gcc-benchの凍結 (定常WL) | 31cyの内訳確定。F1d投資判定の材料 |
| 1 | **F1d: テンプレートJIT** — AArch64手書き (±dynasmrt)、Craneliftなし。F1a〜F1cのフロント資産 (ブロック選定・脱出モデル・カバレッジ・決定性ゲート) を再利用 | ADR-0013の解凍条件を構造で満たす: 税の消滅 (数十kB) + 定常WL (gcc定規)。目標**185+ MIPS** (v86の160〜185が登れると証明済みの高さ) |
| 2 | **ブロック粒度ADR (案B再訪)** — icount式切り直しで決定性無傷。JITブロック内チェックポイント除去 + C14 dead-flags解禁。門番: モード間クロスチェック新設 | QEMU TCG相場 5〜15cy/命令 = **200〜600 MIPS圏** |
| 3 | **wasmバックエンド解凍** — 同じフロントにwasm生成を再接続 | ブラウザでv86級 |

各Stageの終わりに判定し、負けたら台帳へ (ADR-0014の方法は不変)。
Stage 1が負けた場合 (ネイティブでもJITが黒字にならない) はTier 6へ進み、
本件は台帳で寝る — **選択肢は棄却せず順番を決めただけ**である。

## やらないこと

- Cranelift再導入 (リンク税の実測+25%、ADR-0013)
- copy-and-patch (意味論の二重管理)
- インタプリタ単体でのブロック粒度化 (C5の実証)
- Dolphin式spin-loop検出 (MMIO副作用の見落としで25%退行→revertの前例)
