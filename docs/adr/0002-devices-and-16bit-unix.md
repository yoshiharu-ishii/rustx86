# ADR-0002: CPU以外の装置を作り、16bit UNIX (ELKS) を起動する

- ステータス: 提案 (2026-08-07)
- 前提: [ADR-0001](0001-16bit-cpu-and-cosim.md)

## 背景

リアルモード8086のCPUが動き、co-simで検証できるようになった。だが
**CPU単体には意味がない**。CPUは装置に繋がって初めて計算機になる。

次に何を動かすかで、作るべき装置が決まる。候補は3つあった。

| 候補 | 必要なもの | 到達の遠さ |
|---|---|---|
| FreeDOS | BIOS HLE、テキストVRAM、IVT、**INT 21h のDOSサービス群** | 近い |
| ELKS (16bit UNIX) | BIOS HLE (ディスクのみ)、テキストVRAM、IVT、**PIC/PIT/UART** | 近い |
| 32bit Linux | プロテクトモード、ページング、PIC/PIT/UART、virtio-blk | 遠い |

最終目標は32bit Linuxだが、そこまで何も動かないまま進むのは危うい。
途中に「動いた」と言える到達点が要る。

判断の軸は**その作業が最終目標でも生きるか**である。

## 決定

### 1. 次の目標を ELKS の起動に置く。FreeDOS は飛ばす

[ELKS (Embeddable Linux Kernel Subset)](https://github.com/ghaerr/elks) は
8086/8088/186/286 で動く16bit UNIXで、旧名を Linux-8086 という。
Linuxの初期フォークを16bit環境向けに保守し続けているプロジェクトで、
フロッピー/HDDイメージが配布されている。

FreeDOSを選ばない理由は、**INT 21h のDOSサービス群が完全な捨て仕事になる**ため。
DOSのファイル操作やメモリ管理をホスト側で実装しても、Linuxに向かうとき1行も残らない。
ELKSなら固有の追加はディスク読み出しだけで済む。

系譜としても、ELKS → Linux は「UNIXの16bit実装から32bit実装へ」という
自然な流れになる。

### 2. 装置は「両方の道で使うもの」から順に作る

- **割り込み機構 (IVT ディスパッチと IRET)** — OSは自分のハンドラを登録して
  割り込みを乗っ取る。今の「INT命令をフックする」方式では足りない
- **8259 PIC** — 割り込みコントローラ。32bit PCでも同じチップを使う
- **8254 PIT** — タイマー。OSのスケジューラが時を刻むのに要る。これも同じチップ
- **UART 16550** — シリアルコンソール。Linuxのコンソールもこれ

この4つは32bit Linuxでもそのまま使う。**捨てにならない順に作る**。

### 3. ディスクは BIOS INT 13h の HLE で済ませ、FDC/IDE は実装しない

フロッピーディスクコントローラを回路として再現するのは数千行の仕事だが、
`INT 13h` を「ディスクイメージの該当セクタをメモリにコピーする関数」として
実装すれば数十行で済む。ELKSはBIOS経由のディスクドライバを持つため、これで足りる。

将来Linuxに向かうときは virtio-blk を実装するので、この部分は置き換わる。
**唯一の捨て仕事だが、安い**。

### 4. 画面はテキストVRAM (0xB8000) を実装する

DOSやUNIXのコンソールは、BIOS経由ではなくビデオメモリに直接書く。
80×25の文字+属性バッファとして実装し、ホスト側で描画する。
rustboyのPPUに比べれば遥かに単純である。

### 5. NetBSD は中間段にしない

NetBSD/i386 は386以上・プロテクトモード・ページング前提で、しかも現代的な
フルカーネルなので**要求する装置がLinuxより重い**。Linuxには `bzImage` を
直接ロードする起動プロトコルと virtio という「エミュレータに優しい道」が
整備されている。BSDを狙うならLinuxが動いた後の横展開とする。

## 結果

### 得られるもの

- **シェルが立ち上がる**。プロテクトモードもページングも無しに
  「自分のCPUの上でUNIXが動く」に到達できる
- 作業の大半 (割り込み・PIC・PIT・UART) がそのまま32bit Linuxで生きる
- 実OSはCPUの穴を容赦なく突く。co-simでは見つからない
  「命令の組み合わせ」の不具合が露出する

### 代償

- CPUの穴埋めが先に必要になる。far jump/call、IRET、セグメントレジスタの
  PUSH/POP、LES/LDS、XLAT、IN/OUT、186命令群 (PUSHA/ENTER/PUSH imm 等)
- 装置が増えるとco-simでの検証が効かなくなる領域が出る。
  co-simは1命令単位の検証なので、装置の状態遷移は別の方法 (実OSを動かす) で見る
- INT 13h HLE は Linux に向かうとき捨てる

## 検討した代替案

**いきなり32bit Linuxを目指す**: 到達までに動くものが何も無い期間が長すぎる。
途中で何が壊れているのか切り分ける手段も乏しい。

**DOSの .COM を動かす段を挟む**: 装置ゼロでCPUの慣らし運転ができる利点はあるが、
INT 21h を数個実装する手間の割に到達点が小さい。ELKSに直行しても
CPUの穴は同じように露出する。省略可能な段とする。

**Minix 2 (8086版)**: 16bit UNIXとしては正統だが、現代の環境でのビルドと
イメージ入手に手間がかかる。ELKSの方がプリビルドイメージがあり実用的。
