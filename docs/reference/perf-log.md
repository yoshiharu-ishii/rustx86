# 最適化の実験記 (時系列・追記専用)

[perf.md](perf.md) が「地図」(現在地・カタログ・規律)、ここが「物語」—
日付つきの実験の経過と謎解きの記録。横断の教訓は [pitfalls.md](../explanation/pitfalls.md) へ、
判断の理由は [ADR](../adr/) へ。

## 2026-08-10: B4後の現在地とプロファイル

| 経路 | シェル到達 | 実効速度 |
|---|---|---|
| vmlinux 直接ロード | 580M命令 / 8.8s | 66.2 MIPS (P1a後16.3s → C4 → B4で半減) |
| wasm (headless) | 600M / 13.6s | 44.2 MIPS (P1a前は50〜66s — 4倍弱) |
| ブラウザ実機 | 21s (ユーザー実測) | P1a後45s → P1b後38s → 21s |
| スナップショット復元 | — | 0.1〜1s (起動しない、が最速) |

プロファイル (boot中サンプル上位): cpu::step 33% (フェッチ+ディスパッチ) /
modrm 13% / memmove 12% (CPU控え+REP) / translate_for 8%。

**「なぜ~30 MIPSどまりだったのか」の当時の理解**: 1命令34ns = M1の約110サイクル。
毎命令「フェッチ→プレフィクスループ→巨大match (間接分岐の予測ミス) →
ModRM再デコード→実行→帳簿」を踏む古典的スイッチ型インタプリタの相場 —
コードが悪いのではなく構造の上限。この理解がP1 (dcache) 以降の全設計を導いた。

### つぶした順 (2026-08-10深夜時点の総括)

```
済み:    A1 A2(寝) B1 B2 B3(寝) B4 B5(寝) C1 C2 C4 C4b C5(寝) D2(寝) E1 E2 E6
         — 13→78 MIPS
方針転換 (ユーザー決定): Tier進行の前に100 MIPSを取り切る。
理由「エミュレータの速さは以後すべての検証の単価」。
経過:   C1 -3〜4% (期待10〜25%はB4前の前提)、C4b -17% (memmove 11%の正体は
        Cpu丸ごと控えだった)。以降は全滅: D2・TLB配列化・C5 (+10%悪化)・
        B5ブロック化 (+8%悪化) — インタプリタ内の再配置はもう動かない
結論:   素で~78 MIPS。構造の上限に到達 — 100へはF1テンプレートJITが本命昇格
```

**B3の教訓**: 最適化の取り分は積み木ではない。B4が「毎命令の固定費」を先に
食い尽くしたので、同じ費目を狙うB3にはもう払い戻しが残っていなかった。
カタログの期待値は**着手時点の前提**の値であり、先行する最適化が前提を書き換える。

## 2026-08-11: ホスト横断の実測 (同じイメージ・同じ命令数 — 全マス完了)

| ホスト | ネイティブ bzImage (970M) | ネイティブ vmlinux (580M) | wasm bzImage (1000M) | wasm vmlinux (600M) |
|---|---|---|---|---|
| M1 MacBook Air (2020) | 10.7s / **90.7 MIPS** | 7.3s / 79.5 | 16.2s / 61.7 | 10.0s / 60.3 |
| Ivy Bridge素のWindows (2012) | 23.9s / 40.6 | 15.2s / 38.2 | 36.9s / 27.1 | 21.6s / 27.8 |
| 同マシンのVirtualBox VM (Ubuntu) | 26.1s / 37.2 | 16.0s / 36.3 | 36.0s / 27.8 | 21.3s / 28.2 |

- **仮想化の税はわずか5〜9%、wasmではほぼゼロ** — エミュレータは純粋な
  ユーザー空間演算でVM exitをほぼ起こさない。M1との2.4倍差の正体はCPU世代差
- **wasm/ネイティブ比はM1で68%、Ivy Bridgeで67%** — V8のwasm JIT効率はISA非依存
- **命令数は全3ホスト×2経路×2ランタイムでビット同一** — 決定性がOS・ISA横断で成立。
  Tier 8 (ホスト混在のスナップショットfork) への布石
- 2012年の企業PCでもwasm 27 MIPS = ブート37s — 「古いPCにブラウザだけでLinuxが
  立つ」の下限値

## 2026-08-11: F1b-1 (ロード) — ワッシュ、そして時計過払いの発見

## 2026-08-12 互換の代金を測る — test386完全合格の前後で交互A/B

test386完全合格 (PR #78) はタダではない。毎命令に足したもの:
データアクセスのセグメントlimit検査 (data_addr)・A/Dビット反映の空チェック
(flush_ad)・フォールト控えの条件拡大 (paging時のみ→PE時)・POPF/回転の
フラグ規則。命令数は**580Mで不変** (意味の同一性はOS起動回帰が保証) なので、
差は純粋に毎命令の単価。

計測: `bootphase images/vmlinux-lts` を互換前 (main@697b7b4、worktreeで焼き直し)
と互換後 (main@e72c2c7) で交互に5周。

| round | 互換前 | 互換後 |
|---|---|---|
| 1 | 8.2s | 9.0s |
| 2 | 8.3s | 9.1s |
| 3 | 8.2s | 9.4s |
| 4 | 8.3s | 9.1s |
| 5 | 8.3s | 9.4s |

**約+10% (~70 → ~64 MIPS)**。これは「正しさの代金」であり払って正解 —
ただし取り返す道はある。検査のほぼ全ては Linux の平坦セグメント
(base=0/limit=4GB) では**恒真**なので、ロード時に平坦と判定して控えれば
1分岐で飛ばせる (カタログ S1)。JIT (F1c) はこの検査ごと生成コードに
畳み込めるので、互換税はJIT時代には別の形で消える見込み。

## 2026-08-12 互換税の取り返し S1〜S3 — 見立ては外れ、-2〜4%で打ち止め

S1 (平坦セグメント高速路) が本丸のはずだった — 検査はLinuxの平坦セグメント
で恒真だから。ところが単独で**-2%**しか返らない。S2 (flush_adの空チェックを
インライン化 — 毎命令に非インラインcallが1本入っていた) で合算-3〜4%、
S3 (TLBエントリ16→12バイト、旗をbaseの下位ビットへ) は熱ノイズに埋もれて
単独寄与を判定できず (構造としては正しいので採用)。

| round (冷却後) | main | S1+S2+S3 |
|---|---|---|
| 4〜8の帯 | 9.1〜9.5s | 8.9〜9.3s |

教訓: **「検査のコスト」は検査の分岐ではなくコードの嵩** — 分岐自体はM1の
予測が隠す (B5/C5と同じ構図)。恒真の検査を飛ばしても、増えたコードがI側を
圧す分は返らない。残り~6%は追わず、F1c (Cranelift) で検査ごと生成コードに
畳み込む側に賭ける。

## 2026-08-12 F1c関門プローブ — Craneliftの固定費は回収可能、焼きは背景スレッド前提

wasm版jit-probe (F1a入口の関門) と同じ問いをネイティブ/Craneliftに。
道具は tools/jit-probe-native (使い切りの独立クレート、coreは無依存のまま)。
regs配列へのload/ALU/store連鎖をuopブロックに見立て、opt_level none/speed両方。

| 指標 | 実測 (M1) | 備考 |
|---|---|---|
| 呼び出し | ~3ns/ブロック | wasm版の7nsより安い (C ABI直呼び) |
| uop単価 | 0.28〜0.83ns | インタプリタ16〜36nsの20〜50倍の頭上 |
| 焼き | 53〜76µs (4〜8uop)、276µs (40uop) | wasm手組み6.3µsの~10倍。noneとspeedでほぼ差なし (下部構造が支配) |

損益分岐 ≒ 600実行/ブロック (8uop、70µs÷120ns節約)。熱ブロックの平均実行数は
~15k (580M×カバレッジ0.8÷31k頭) なので**個々のブロックは楽に回収**する。
問題は総額: 31,441頭×~70µs ≒ **2.2秒** — 9秒のブートに前払いで載せたら台無し。
ネイティブはwasmと違ってスレッドがあるので、**焼きは背景スレッド**
(インタプリタが走り続ける裏でコンパイル、できた物から差し替え) が設計要件。
決定性は従来どおり「毎命令の受付点」(案A) を守れば、差し替えタイミングに
よらず命令数は不変にできる — ここはF1c設計 (別ADR) で詰める。

## 2026-08-12 F1c-a 骨格が立った — 決定性ゲート一発合格、カバレッジ16.8%で早くも黒字

jit-native (Cranelift、ADR-0012) の骨格: wasm生成器と同じ意味論契約をCLIFで
写し、焼きは背景スレッド (据え付け時にcollect時ページ世代と照合 — 世代落ち
107件が実際に発生し、ガードが仕事をした)。

初回実行で:
- **決定性ゲート合格**: JIT on/off で命令数 (576,000,000) もシリアルFNVも一致
- **冷間ペア -6%** (12.5→11.7s)、熱間の交互A/Bで -2〜3% (on 4/4勝)
- カバレッジ16.8%・平均ブロック長4.4 — **wasm (F1b-3) と同じ数字で、
  wasmは微赤字、ネイティブは黒字**。ヘルパ税とJS境界の差が単価に出た形

次 = F1c-b: TLBヒット経路とセグメント検査を生成コードに畳み込む (単価)、
その先にブロック連結 (F1c-c)。カバレッジの梃子はwasmで学んだ機構
(タイル張り・走路焼き・永続台帳) が既にcore側にあるので、単価が先。

## 2026-08-12 F1c-b1 TLBインライン — 決定性維持、効果はカバレッジ16.8%ではノイズ内

生成コードにTLBヒット経路を畳み込んだ (ld32/st32/RMW)。coreはrepr(C)の契約と
番地表 (JitLayout: tlb/mem/hidden/vram) の拡張のみ。高速路の条件は保守的 —
ページ跨ぎ・TLBミス・旗不足 (読み:U、書き:W|U|D)・RAM外・VRAM窓は全部
ヘルパ (原本) へ落とすので、**高速路が通るときに限り意味が一致する**構造。
RMWのインライン側はalu_coreのcc材料書き出しを流用 (二重実装なし)。

- 決定性の指紋 (命令数576M+シリアルFNV): on/off一致を維持
- 門番: test386 PASS / cosim / workspace 24suite 全緑
- 冷却A/B 8周: 前半5周はon勝ち (最大-2.3s)、後半ワッシュ。off側が
  12.3〜15.5sで暴れる晩で、理論効果 (~0.3〜0.5s @ カバレッジ16.8%) は
  ノイズに沈む。**F1b-1/2と同じ「単独では測れない資産」** — カバレッジが
  上がった時に単価として効く土台なので採用

結論はまた同じ所へ帰る: **梃子はカバレッジ (16.8%)**。次はopstatsで
語彙外uop分布を採り直し (wasm時代の実測は語彙内81%)、F1c-c (連結) か
語彙拡張かをデータで決める。

## 2026-08-12 ネイティブの語彙分布 (opstats) — 次の語彙はshift・movzx8・8bit ALU族

jboot --features opstats で採り直し (wasm時代のF1b-3と同じ流儀):
語彙内77.4% / 語彙外22.6%。語彙外の上位:

| uop | 動的数 |
|---|---|
| shift r (シフト/回転 レジスタ形) | 29M |
| movzx8 r,[m] | 19M |
| test8 | 13M |
| grp1-8 / grp3-8 / alu8 (8bit ALU族) | 20M |

この4家族 (~85M/130M) を語彙に足せば語彙内~92%。カバレッジ16.8%と
語彙内77.4%の差は分断 (語彙外1命令が走路を切る) なので、頻出の
分断犯を消す効果はブロック長に複利で効く。**F1c-b2 = この語彙拡張**。
シフトのccはlazy flagsの材料形が違う (shift_rot参照) — cc_op拡張が要る。

## 2026-08-12 F1c-b2 語彙v2 — カバレッジ16.8→29.6%、冷却A/B 8周全勝 -7〜9%

分布実測どおり shift r・movzx8/16・test8・8bit ALU族・mov8 (読み形) を語彙化。
capsゲート (CAP_VOCAB2) でwasm生成器 (凍結) には渡さない。実装の型は3種:
- **インライン**: movzx・8bit ALU/test/cmp (alu8_core = cc_w=0の材料書き出し、
  AH形のバイト抽出/挿入込み)、ld8はTLB高速路つき
- **ヘルパ完結 (eager flags)**: shift r (shift_rotの意味論はcc材料に畳めない)、
  grp3b8のNEG (CF上書き)。#PF不能なので脱出も不要 — 一番安い形
- **ヘルパのみ**: ld16 (頻度2M、インライン化は分布が要求してから)

| 指標 | b1 | b2 |
|---|---|---|
| 語彙内 (動的) | 77.4% | **94.7%** |
| カバレッジ | 16.8% | **29.6%** |
| 平均ブロック長 | 4.4 | 4.6 |
| 冷却A/B | ノイズ内 | **off 12.3〜13.5 vs on 11.5〜12.3 (8周全勝、-7〜9%)** |

決定性の指紋 (576M+シリアルFNV) はon/off一致を維持。

**次の梃子はF1c-c (連結)**: 語彙94.7%でカバレッジ29.6%ということは、
ブロックがjccごとに切れる4.6命令 (x86の基本ブロック長そのもの) が壁。
jccの不成立側をブロック内で続ける「両側焼き」= B4 (-43%) のJIT版が本命。

## 2026-08-12 F1c-c1 連結 + c2 閾値掃引 — ブロック長5.9、カバレッジの天井30%の正体へ

**c1 (jcc両側焼き、CAP_CHAIN)**: 途中のjccを「成立なら ip書いてk+1で退出、
不成立なら同じブロックを続行」に。ブロック長4.6→5.9、入回数37M→28M
(ディスパッチ9M回削減)。b2との速度差はノイズ内 (~0.15s < 床) — 構造資産。
決定性指紋は維持。

**c2 (熱閾値の掃引)**: 8 / 64 / 256 を実測:

| 閾値 | カバレッジ | 据付 | 発見 |
|---|---|---|---|
| 8 | **27.6% (悪化)** | 13165 | **早すぎる焼きはタイルの育ちを止める** — JITブロック内を走ると内側の頭 (head_pending) に熱が乗らない |
| 64 (現行) | 29.3〜29.6% | 7347 | |
| 256 | 29.7% | 4382 | 同等。立ち上がりが遅いだけ |

**閾値は梃子ではない。** 30%で飽和する天井の有力容疑は **tick境界の入場制限**
(step_cachedの `jn <= budget`、budget = tick_countdown min chain残 — 長い
ブロックほどtick窓 (64命令) の残りで入場を拒否され、その区間はインタプリタが
走る)。次 = F1c-c3: 入場判定の実測 (拒否回数のカウンタ) → ブロックに
「最大n命令で途中退出」の口を足してtick窓の残りまで走らせる案の検討。

## 2026-08-12 F1c-c3 入場診断 — 天井の解剖と、bzImageでの初の実効

入場拒否のカウンタ (jit_denied) を常設して天井を解剖した:

| ワークロード | カバレッジ | 無ブロック | 予算不足 | tick直後 |
|---|---|---|---|---|
| vmlinux (576M) | 29.3% | **49M** | 5M | 9M |
| bzImage (968M) | **41.4%** | 80M | 12M | 26M |

- **主因は「無ブロック」= 冷コードの裾野** (閾値64未満しか実行されない初期化
  コードの山)。プレウォーミング禁止 (ADR-0012) の下では、ブート様の
  ワークロードに固有の限界 — 熱いところは既に獲れている
- 予算不足 (tick窓の残り < ブロック長) はvmlinuxで~5%相当、bzImageで~7%相当。
  次に獲るならここ (「実行時上限つき途中退出」の口) だが、複雑さと相談
- **bzImageの冷却A/B 6周全勝: off中央~20.0s vs on ~18.2s (-9〜12%)**。
  解凍ステブ (熱ループ) が乗ってカバレッジ41.4% — JITが効く形。
  ユーザーの冷間基準14.2sに換算すると**~12.8s相当** (フルブート10秒まで残り~2.8s)

環境注記: この晩の絶対値は長時間コンパイルの熱ダレで大きく劣化
(off側が18.6〜23.3sで暴れる)。相対 (対の勝敗と差分) だけを信じる。

## 2026-08-12 F1c-c4 予算つき途中退出 — 「予算不足」を消滅、bzImageカバレッジ46.5%

ブロックに実行時上限 (Machine::jit_budget、coreがenter直前に書く) を渡し、
生成コードがopごとに照合して**境界ちょうどで完全実行済みの途中退出**をする。
tickの位置は不変 = 決定性は保たれる (vmlinux/bzImageとも指紋一致を確認)。
JitHookにbudget_aware旗 — wasm凍結世代はfalseで従来の入場規則のまま
(wasmのjit-checkゲートも緑)。

| | c3まで | c4 |
|---|---|---|
| 予算不足 (入場拒否) | 5M/12M | **0** |
| カバレッジ vmlinux | 29.3% | 31.3% |
| カバレッジ bzImage | 41.4% | **46.5%** |

冷却A/B (bzImage) は5/6勝で-8〜13%帯を維持 — c4単独の上積みは今夜の熱床
(ファンレスAir、off側~21s) では分離不能。構造 (拒否класс消滅+5pp) で採用。

残る天井は「無ブロック」= 冷コードの裾野のみ。**次の正確な計測は冷間の
朝一で基準を取り直してから** — 同一バイナリの絶対値が晩に1.5倍暴れる環境で
これ以上の微差は読めない。

## 2026-08-12深夜 jbootの絶対値の正体 — cranelift依存のコードレイアウト税

ユーザーの指摘「熱でも処理能力でもなく、単純に処理の問題」を追った結果、
**別バイナリの絶対値を比べていた**という計測の落とし穴を発見した。

同じ vmlinux 576M命令を、条件を1つずつ揃えて2バイナリで測った:

| バイナリ | 条件 | 秒 |
|---|---|---|
| bootphase (core example) | run 10M | 9.5〜10.9 |
| bootphase | run **2M** | 9.8〜10.0 |
| bootphase | run 2M + **Box化** | 9.7〜9.8 |
| **jboot (jit-native bin)** | run 2M, Box, JIT=off | **12.0〜13.2** |

Machine構成・Box化・run粒度・serial処理を**全部揃えても** core-example 9.7s
vs jit-native bin 12.7s。差は**リンクされる依存 (cranelift ~3MB) だけ**。
ループボディを空 (m.runのみ) にしても jboot は12.7sのまま — ハーネスの
ロジックではなく、**巨大な無関係コードのリンクでホットループ機械語の
アラインメント/iキャッシュ挙動が変わる**実在の現象 (Mytkowicz 2009
"Producing Wrong Data Without Doing Anything Obviously Wrong")。

### 教訓 (pitfalls行き)

- **絶対値は同一バイナリ内のA/Bでのみ信じる。** 別バイナリ間の絶対値の
  比較は、コードレイアウトで20%以上動くので無意味
- **JITのoff/on (-9〜13%) は正しい** — 同一jbootバイナリの相対だから
- ただし今日の記述「冷間14.2s換算で~12.8s相当」等、**jbootの相対を
  bootphaseの絶対へ貼り付けた換算は撤回する**。真の絶対の物差しは
  bootphase (vmlinux 10s / bzImageフル 14.2s、いずれもJIT非対応)。
  JITの絶対実効を同じ土俵で測るには bootphase にJITフックを載せた
  ハーネスが要る (次の宿題)
- 本番 (Firecracker/ネイティブ配布) は cranelift をリンクした
  バイナリなので、レイアウト税込みの jboot 側の絶対値の方がむしろ
  本番に近い — LTO/PGOでレイアウトが再び動くまでは

## 2026-08-13 F1c-d1 世代落ちヘッドの再焼き — 負け (台帳へ)

仮説: `JitRt.compiled` (HashSet) が一度焼きに出した頭を永久スキップするため、
ページ世代が進んで無効化されたブロックは再び熱くなってもインタプリタ落ちの
まま = 取りこぼし。compiled を head_pa→collect時世代 のHashMapにして、
世代が動いた頭は焼き直す (実装はPR #92の初版コミット 52d7d8a — revert済み。
再訪時はここから復元する)。

結果 (bzImage 968M、冷却A/B 6周): **旧4勝・新1勝・1分**、中央値 18.0s vs 18.5s。
決定性ゲートは合格 (on/off 命令数・シリアルFNV一致)。速度では取れない。

意外な副作用が決め手: 再焼き1558発火で据付は+16% (10398→12088) なのに、
**JIT実行命令はむしろ減った** (450M→415M、カバレッジ46.6%→42.9%、
入回数80M→70M、平均ブロック長5.6→5.9)。再焼きされた頭が既存の
タイル/連結の形を組み替え、細かい入口が消えた分だけ総実行が痩せたと
見える (機序の完全解明はしていない — 深追いしない)。

教訓: ブート様WLの世代落ちヘッドの多くは「二度と同じ形で熱くならない」
使い捨てページ (解凍ステブ等)。再焼きは焼き代が無駄なうえタイルの育ちを
乱す — c2「早すぎる焼きはタイルの育ちを止める」と同族の現象。

再訪条件: 自己書き換えが定常的なWL (DOSゲーム常駐・ゲスト内JIT等) で、
世代落ち起因のカバレッジの穴が数%を超えると実測されたとき。
