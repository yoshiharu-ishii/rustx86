# ADR-0010: test386で「CPUの互換を完璧にする」— 速さの前に正しさを積む

日付: 2026-08-12
状態: 採用 (進行中)

## モチベーション (なぜ今、互換なのか)

きっかけは速さの頭打ちである。フルブート10秒はネイティブvmlinuxで達成した。
その先の速さは、凍結中の封 (wasm JITのTLBインライン、ADR-0008) か
Stay中の路線 (Cranelift、ホットコード検出) を開けないと届かない —
そして開けない理由 (決定性・運用判断を持ち込まない [ADR-0009]) は変わっていない。

一方で正しさの側には、**明確に登れる山**が残っていた:

1. **OSが起動する ≠ CPUが正しい。** 3OS起動回帰は「OSが踏む命令列」しか
   検証しない。実際、test386を導入した初日に4つの嘘が見つかった
   (JCXZのアドレスサイズ無視、mov csの#UD素通り、far call/retfの
   オペランドサイズ無視、LSS未実装)。**全部、OSは踏まないがCPUとしては嘘**
   の領域である。Linuxが動いていたのは、Linuxがそこを踏まないだけだった
2. **目標 (v86のOSリスト) は互換の山。** Windows 9x/2000・ReactOS・
   Android-x86・FreeBSDに続く道は、例外配送・TSS・V86モード・LDTという
   「OSごとに踏み方が違う」区画を通る。ここを個別OSのデバッグで潰すと
   「動くまで叩く」の繰り返しになる — **先にCPU総合テストで面として塞ぐ**
   方が、後のOS追加が全部安くなる
3. **PRで壊される方が怖い** (ユーザー方針 2026-08-12)。CPUの互換は
   一度手に入れたら**門番で恒久化**しないと、次の最適化PRが静かに壊す。
   test386は数秒で回るので常時PR門番にできる — cosim (単発命令) の上に
   「命令の組み合わせ・モード遷移」の層を積む

要するに: **速さは封を切らないと進まないが、正しさは手を動かせば進む。
そして正しさの山を登り切ると、目標のOSリストへの道が全部舗装される。**

## 決定

- test386.asm (86Box/PCem界隈の定番CPUテストROM、GPLv3) を互換ピラミッド
  L1の審判として導入する。**完走 (POST FF) + EE出力の期待値一致**を合格とする
- ROMは配布せず `tools/fetch-images.sh test386` でソース取得+nasmビルド
  (OSイメージと同じ流儀 — 入手経路をスクリプトに一意化する)
- 生ROM実行モード (`Machine::boot_rom`) を設ける。BIOS HLE (CS==0xF000の
  肩代わり) をバイパスし、リセット姿勢 F000:FFF0 から素で走らせる
- gapは**実CPUの挙動に合わせて**core側を直す (テストに合わせた特例は作らない)。
  修正のたびに cosim + 3OS起動回帰で退行なしを確認する
- 全緑になったら「CPU互換」として**常時PR門番**に据える (掲示板にも1行足す)

## 現在地と道のり

```
POST: 00 ─────────────── 08 ──────────────────────── EE ── FF
      実モード区間 ✅      保護モード区間 (いまここ)      算術出力照合
      Jcc/loop/call/      LLDT → 例外配送(エラーコード) →
      string/seg mov      TSS → ページング境界 → V86
```

- 保護モード区間には「まだpanicで止める」と明記された未実装が並ぶ
  (#GP配送・ゲート型・LDT)。test386はそれを**上から順に踏んでくれる**ので、
  実装の順番はPOSTの足跡が決める — ロードマップを推測で引かない
- test386は自称 incomplete (実機検証されていない項目もある)。期待値と
  食い違ったときは test386 のソースと .lst まで下りて裁く

## 棄却した代替

- **SingleStepTests/80386 (単発命令のJSONベクタ)** — cosim (L0) と役割が
  重複する。欲しいのは「単発を超えた組み合わせ」の層
- **OSを増やして面を塞ぐ** — ReactOSやWin9xを直接デバッグする案。
  1OSごとに「動くまで叩く」を繰り返すことになり、同じCPU gapを
  別々の症状として何度も踏む。CPU総合テストで先に面を塞ぐ方が安い
- **エミュレータ済みの他社実装を写す** — 意味論の原本は実CPUの仕様と
  オラクル (Unicorn/実機)。写しはバグごと写す
