# ロードマップ — 深さ (Tier) と広さ (箱)

軸が2本ある。混ぜると両方の意味が壊れるので分けてある。

```
  深さ (Tier) ── 何が動くか
  ┌────┬────┬────┬──────────┬────┬────┬──────┬───────┬──────┐
  │ 1 ✅│ 2 ✅│ 3 ✅│ 4 ★節目  │ 5  │ 6  │  7   │   8   │  9   │
  └────┴────┴────┴──────────┴────┴────┴──────┴───────┴──────┘
       16bit 32bit   Linux     NW   GUI ネイティブ μVM   x86_64
          │     │              │    │
  ────────┼─────┼──────────────┼────┼──────
          B1    B3            B2/B5  B4

  広さ (箱) ── どう触れるか
```

**Tier は「何が動くか」の深さ**。当初は Tier 4 (Linux起動) を完成としていたが、
そこに着いてみたら先が見えた — 長期目標は **x86_64化** (Tier 9、別リポジトリ) で、
その手前に **マイクロVM化** (Tier 8) が居る。

作りたいのは、**ときにはFirecrackerっぽく (ヘッドレスで軽量VMを大量に)、
ときにはVirtualBoxっぽく (画面つきの1台を対話的に) 振る舞えるアプリ**である。
それを依存ゼロ (KVMもHyper-Vも管理者権限も不要)・決定的 (ビット単位で再現する
実行、スナップショットからの分岐起動)・どこでも動く (ブラウザ/ネイティブ) の
3軸で作る — マイクロVM側の姿を俗に言えば「KVMを使わないFirecracker」になる。

順序の原則は **「タブの中で完結するものを先に、外に出るものを後に」**。
ネットワークだけは踏み台 (EC2・ドメイン・TLS) の用意が要るので最後に置いた
([ADR-0005](adr/0005-local-first-roadmap.md))。

着手順は固定しない — そのときやりたいTier/箱から進める。

**「作らないもの」の判断は動いた** (2026-08-15 整理)。[ADR-0011](adr/0011-tier-redraw-after-compat.md)
では「PCIバス・ISAバス・グラボは作らない」としていたが、その後 **PCIバスは作った** —
RTL8029をLinuxに見せるには設定空間の列挙が要ったからである ([ADR-0017](adr/0017-network-isa-first.md))。
いまの判断はこう:

| | どうする | 理由 |
|---|---|---|
| PCIバス | **作った** | 設定空間・BAR・スロット。`bus/pci/` ([ADR-0017](adr/0017-network-isa-first.md)) |
| ISAの固定番地とIRQ配線 | **作った** | 番地の表と配線。`bus/isa/` ([ADR-0018](adr/0018-devices-chip-card-bus.md)) |
| VGA mode 13h | **作る** (2026-08-15 決定) | 0xA0000 の 320×200×8bpp + DACパレット**だけ**。**planar/CGA/EGA・VBEはやらない** — 底が無いのはVGA互換の全体であって、mode 13h 単体は有界である |
| グラボ (GL) | 作らない | ADR-0011 のまま。GUIは 6g の古典デスクトップまで |

| Tier | 到達点 | 状態 |
|---|---|---|
| 1 | 16bitリアルモードCPUが命令を正しく実行する | ✅ |
| 2 | **ブラウザの画面でELKSのシェルが叩ける** | ✅ |

## 刻むマイルストーン (2026-08-10 制定)

Tierとは別に、**「動いた」と叫べる節目**を順に刻む。tetris が時計の
受け入れテストだったように、節目は機能一覧ではなく**遊べるもの**で判定する。

```
1. 100 MIPS  ✅達成  — 2026-08-13。JITではなく**ホットパスの付帯処理の一掃**で
                      届いた (ADR-0014/0015、ベスト9.5s=102 MIPS)。F1c Craneliftは
                      リンク税で負けて凍結・削除 (ADR-0013)
2. ANSI端末DOOM     — グラフィックス無しで刻む中間マイルストーン。
                      doomgeneric + ANSIバックエンドをi386静的ビルドして initramfs へ。
                      79 MIPS は DOOM が設計された 486DX2-66 を上回る — 現状でも動く算段
3. Tier 6a フレームバッファ
4. VGA DOOM         — **Tier 6 の合格判定 (音付き)**。fbdev・キーボード・音・性能の総合試験
```

節目2と4の間に**別ルート**がある: **FreeDOS DOOM**。DOSのDOOMはDOS4GWで32bit
プロテクトモードに入る。2026-08-15 に下見したところ、要るものは3つだった:

| 要る物 | 状態 |
|---|---|
| VGA mode 13h (0xA0000 の 320×200) | **作る** (6a と同じ配管。上の表で決定) |
| **ハードディスク像** | 未 — `DOOM1.WAD` だけで4.2MBあり、**1.44/2.88MBのフロッピーには載らない** |
| DOS4GW / DPMI 互換 | 未検証 (test386全緑なので素性は良い) |

**当初「fbdev+Xよりずっと簡単」と書いたが、ディスクの壁が判明して差は詰まった。**
ANSI端末DOOM (節目2) は画面もディスクも要らない (initramfsに入れるだけ) ので、
**今のところ最短は節目2のまま**である。

**箱 (B) は「どう触れるか」の広さ**で、Tierと並行して進む。
深さは増えないが、増えないからこそTierに混ぜない。

| 箱 | 到達点 | 状態 |
|---|---|---|
| B1 | **マシンを選べる箱にする** (左メニュー、プロファイル) | ✅ |
| B2 | メディア投入 (フロッピー / ISO を入れる口) | |
| B3 | PCスピーカー (PITのチャンネル2) | |
| B4 | 画面の格上げ (フレームバッファ) | |
| B5 | **Web Worker + OPFS への移行** (HDDとタブ固まりの解決) | |

### 「カードを挿す」抽象はまだ半分 (2026-08-15 判断)

- **PCI**: `PciHost.slots[32]` に `plug(slot, PciFunction)` で挿す形は**実在する**。
  ただしスロットに入るのは**名乗りだけ**で、装置の実体は `Devices.net` に居る。
  両者を繋いでいるのは `mem/mod.rs` の手書き `match (slot, net)` —
  **「スロット3には必ずNICが居る」と人間が書いている**
- **ISA**: 挿す概念そのものが無い。NE2000は本来「スロットに挿してジャンパで
  0x300/IRQ3を選んだカード」なのに、半田付けの8259や8254と同じ名前付きフィールド

**今は作らない。** 器が要るのは「2枚挿す」「機械ごとに構成を変える」ときで、いまは1枚。
手書きmatchは1箇所で実害がない ([ADR-0018](adr/0018-devices-chip-card-bus.md) 決定5と同じ理屈 —
無い振る舞いのために器だけ先に作らない)。**作り時は次にカードが増える瞬間** —
e1000/rtl8139・SB16・ATA のどれかが来たら、`match` に足すのではなくスロットに挿す形へ移す。
なお **I/O経路は実行時間の0.03%** と実測済み (2026-08-15) なので、そこに動的ディスパッチを
置くコストは無視できる — 測る前は言えなかった判断材料である。

### 地力 (Tierにも箱にも属さないもの)

- [ ] **間欠panicの正体** — `RuntimeError: unreachable` が起動中に10回に1回程度。
      2026-08-15 にCIの「4 機能層 — ネットワーク」で初めて顔を出した。
      ヘッドレスのハーネス全部に panic フックを据えた (#148) ので、
      **次に踏んだ走行が名前を出す**。総当たり50周では再現しなかった
- CIの門番の一覧と、見張れていない穴 (TLSなど) は [ci.md](reference/ci.md) が原本

## Tier 1: 16bitリアルモードのCPU

- [x] **1a: 骨格** — ブートセクタの Hello, World が動く
  - ALUグリッド (8演算×6形式 = 48命令を1ハンドラで処理)
  - ModRM 16bitアドレッシング、セグメントオーバーライド
  - BIOSは実装せず INT 10h テレタイプ出力をHLEフック
- [x] **1b: 命令網羅とco-sim検証** — Unicorn Engineをオラクルにした比較実行。
      シフト/回転 (GRP2)、MUL/DIV/NEG/NOT (GRP3)、INC/DEC/PUSH/CALL/JMP (GRP4/5)、
      TEST/XCHG/LEA/CBW/CWD/SAHF/LAHF/PUSHF/POPF、十進補正 (DAA/DAS/AAA/AAS/AAM/AAD)、
      ストリング命令 (MOVS/CMPS/STOS/LODS/SCAS、REP対応)
- [x] **1c: 穴埋め** — far jump/call/ret、IRET、セグメントレジスタのPUSH/POP、
      LES/LDS、XLAT、IN/OUT、186命令群 (PUSHA/POPA/PUSH imm/IMUL 3オペランド/ENTER/LEAVE)。
      co-simにセグメントレジスタとスタック観測窓を追加し、
      **`ENTER` のSP計算バグを1件検出**した (下記)
- [x] **1d: 割り込みと例外の機構** — IVTの実ディスパッチ、IF/TF、割り込み受付タイミング、
      ゼロ除算 `#DE`、シングルステップ `INT 1`、HLTからの復帰。
      **CPUが純粋な関数でなくなった**。1サイクルの流れは
      [アーキテクチャ](explanation/architecture.md#1サイクルに何が起きているか)にシーケンス図がある

## Tier 2: 画面とシェル

「画面に映す」という行為に時間をかけて鍛える段。ここで作るコンソール経路は
Tier 5 の Linux でも Tier 6 の GUI でもそのまま使う。

- [x] **2a: バス** — メモリ空間 (RAM / テキストVRAM `0xB8000`) と
      I/Oポート空間 (PIC `0x20,0xA0` / PIT `0x40-43` / UART `0x3F8`) の
      デコーダ2つ。16bit時代はアドレスが定数なので `match` で足りる。
      **ブリッジ (PCI) は不要** — Tier 5 まで出てこない。
      未接続ポートは `0xFF` を返しつつ番号を控える (OSの装置探索を止めないため)
- [x] **2b: 装置** — 8259 PIC、8254 PIT、UART 16550。
      **3つとも32bit Linuxでそのまま使う** ([ADR-0002](adr/0002-devices-and-16bit-unix.md))。
      PITが挙手 → PICが交通整理 → CPUが命令境界で受け取る、という
      [一周](explanation/architecture.md#なぜpicとpitが要るのか)が通っている
- [x] **2c: ELKS起動** — BIOS HLE (INT 10h/11h/12h/13h/15h/16h/1Ah、IRQ0/1) と
      BIOSデータエリア、8042 (A20)、CMOS RTC を実装。**loginプロンプトまで到達**。
      さらに8042へスキャンコードを流して**rootでログインし、シェルが動く**。
      `cargo run --release --example boot -- images/fd2880.img 50000000 root "uname -a"`
- [x] **2d: ブラウザ化** — WASM + canvas。テキストVRAMを直接描き、キー入力を
      8042へスキャンコードとして流す。**ブラウザ上でブート→login→シェルが動く**。
      `web/index.html`。責務ごとに3つに分けてある:
      `terminal.js` (端末) / `machine.js` (機械を回す) / `main.js` (繋ぎ役)。
      端末は —
      Homebrewテーマ、カーソル (CRTC)、物理キー入力 (Ctrl/Esc/矢印)、
      ドラッグ選択とコピー、スクロールバー付きの1000行スクロールバック。
      **状態のスナップショット** (CPU・装置・メモリ・ディスクを丸ごと控えて戻す)。
      開発用サーバーは `python3 web/serve.py`
- [x] **2e: テキストVRAM** — 80×25の文字+属性バッファ。
      ゲストがBIOSを介さず直接書いた画面が、そのまま映っている

## Tier 3: 32bit化 (2026-08-10 引き直し)

当初の 3a〜3c は完了し、Linux起動 (Tier 4) まで通った。着いてみて分かったのは、
この層の本当の仕事が「32bitで動く」ことではなく、**32bitの世界を使い物になる
速さと道具で支える足回り**だということ。GUI (Tier 6) もマイクロVM (Tier 8) も
ここの地力の上に載るので、Tier 3 を拡張して先にやる。

- [x] **3a: プロテクトモード** — GDT、セグメントディスクリプタ、CR0、特権リング、例外
- [x] **3b: 32bit命令** — `0x66`/`0x67` プレフィクス、`0x0F` 二バイト空間、SIBバイト
- [x] **3c: ページング** — CR3、2段ページテーブル、TLB、A20ゲート
- [x] **3d: 起動の即効薬** — スナップショット起動 (起動済みの機械を控えて秒で再開。
      Tier 8c の前倒し) と vmlinux 直接ロード (自己解凍ステブ = 起動の55%を
      ホスト側ロードで消す。Firecracker と同じ判断)
- [x] **3e: CPU高速化** — **フルブート10秒を達成** (2026-08-10)。
      デコード済み命令キャッシュ (P1a/P1b) → 控えの削減 (C4) → ブロック連結 (B4) で
      13→79 MIPS。ネイティブ 7.3s (vmlinux)、ブラウザのフル起動 23s / vmlinux 15s (実測)、
      スナップショット復帰は数秒。**意味の不変は決定的命令数 (580M/28M) の
      完全一致で毎回証明** — cosim + OS起動回帰の検証網の上で進めた。
      判断は [ADR-0007](adr/0007-cpu-optimization-steps.md)、数字と残り
      (B3ペア融合など。出口条件 ~100 MIPS) は [docs/reference/perf.md](reference/perf.md)
- [x] **3f: 32bitデバッガ** — Linuxマシンはワーカーの中で回るので、
      **覗き見RPC** (postMessage、メソッド許可リスト) で境界を渡した。
      デバッガは機械のメソッドを全部 await で呼ぶ — 同期の機械 (16bit) と
      ワーカーの代役 (Promise) を同じコードで扱う。ブレークポイントは走っている
      機械にも効き、ヒットするとワーカーがループを降りて理由を届ける。
      メモリダンプは線形アドレス — ページング越しにカーネル空間が覗ける
- [x] **3g: スナップショットのファイル書き出し** — 達成。JSONをやめて**バイナリ形式**
      (`core/src/snapshot.rs` の Writer/Reader、RLE圧縮) に。ブラウザから書き出し・
      読み込みができ (`web/main.js`)、`images/linux-booted.snap` として配布もしている。
      CIの「4 機能層 — スナップショット」が毎push見張る

## Tier 4: Linux起動 ← 当初の完成ライン (2026-08 到達)

- [x] **4a: メモリ拡張** — 1MB固定をやめた (MachineProfile)。e820 をゲストに渡す
- [x] **4b: ブートプロトコル** — BIOSは作らず bzImage / vmlinux + initrd を
      直接ロードして32bitエントリへ (QEMUの `-kernel` 方式)。
      ブラウザで Linux 6.18 (Alpine) が起動し、busybox のシェルで遊べる
- ~~4c: virtio-blk~~ → **Tier 4 からは外した** (2026-08-15)。**起動には要らない** —
      Linuxはinitramfsで起動するのでディスクを1バイトも使わないし、「PCIを実装せずに
      済む」という当初の理由もPCIを作った時点で消えた (ADR-0017)。
      **ただし用途が来たら前倒しする**: ディスクにrootfsを置きたく
      なった瞬間 (gccを入れる・Tiny CoreでXを動かす) に要る。
      **PCIができた今、virtio-blk-pci はATAより安い** — 実測でnetbootの
      initramfs-lts に `virtio_pci.ko` と `virtio_blk.ko` が入っており、
      ne2k-pci と同じ手口 (モジュールを抜いてminiに足す) がそのまま使える。
      置き場は Tier 6 のメディア段 (6c/6d の隣) が正しい
- [x] **4d: x87 (FPU)** — f64裏打ちで実装 (2026-08-14、QEMU-tiny/v86と同じ
      割り切り)。スタブが演算のESCを黙って流していた時代、muslのstrtodが壊れ
      `sleep 3` の「3」がbusyboxのparse_durationで20msに化け、ゲストのpingが
      本物のインターネットへ洪水になった (同日の実害が着工の引き金)。
      実装後: printf '%f' 3 = 3.000000、time sleep 3 = 実時間3.01s。
      未実装ESCは trap で止める (黙って流す穴は塞いだ)。
      台帳: 80bit精度そのもの (f80 softfloat) とUnicornオラクルのcosim拡張は
      精度が問題になった実測が出てから

## Tier 5: ネットワーク (2026-08-13 引き直し、[ADR-0017](adr/0017-network-isa-first.md))

旧計画は virtio-net 先行だったが、偵察で崩れた — Alpine lts は virtio-mmio を
カーネル引数で発見できず (`CMDLINE_DEVICES` 無効)、virt フレーバーは PAE 必須で
現行 core では起動しない。装置は「本物」に寄せ、**バスの歴史の順 (ISA → PCI)**
で行く。SLiRP backendは [wsslirp](https://github.com/yoshiharu-ishii/wsslirp) (Go、完成済み —
DHCP/DNS/TCPハーフクローズ/外向きICMPまで実インターネット検証済み)。
境界は「1 WSバイナリメッセージ = 1 Ethernetフレーム」だけ。

- [x] **5a: 踏み台** — wsslirp として独立リポジトリで完成 (TAP/MASQUERADEではなく
      gVisor netstackのユーザーモードNATになった。root不要でどこにでも置ける)
- [x] **5b: ISA NE2000 (DP8390)** — 達成 (2026-08-14)。**1993年のFreeDOSから
      `ping 1.1.1.1` が返る** (NE2000.COM + mTCP)。ELKSも urlget で本物のHTMLを引く。
      coreの境界はフレーム送受だけで、WS等の非決定I/Oは外側 (ADR-0017)
- [x] **5c: PCI + RTL8029** — 達成 (2026-08-14)。PCIバス (設定空間の列挙) を作り、
      **同じ8390コア**をPCIの皮で包んだ。Alpine lts の `ne2k-pci` がカーネル無変更で
      bindし、ブラウザのLinuxから DHCP → ping → wget が通る。
      e1000/rtl8139 は ReactOS/DOS の要求が来たら同じバスへ
- [x] **5c+: TLS** — 達成 (2026-08-14)。`wget https://` が実物のPNGを引く。
      壁は6枚あった: MMX (libcryptoが#UD) → SSE2の語彙の歯抜け → RTCの実時刻
      (証明書の有効期間) → ssl_client + CA束の同梱 → CAの置き場所 (/etc/ssl/cert.pem) →
      /tmp が無い。**CIでは見張れていない** (閉じた世界に信頼できる証明書が無い) ので、
      実インターネット向けの手動E2Eが唯一の番人 (docs/reference/ci.md)
- [ ] **5d: 本測定** (半分達成 2026-08-15) — 定規は `tools/webtest/netbench.mjs`
      (実効速度・**空回り(HLT)の割合**・命令/バイト・取りこぼし)。**受信の取りこぼし
      6〜10%を潰して wget が3〜4倍**になり、命令も 40→19 命令/バイトへ
      ([network.md](explanation/network.md)「受信の速さ」)。残るは TCP over TCP の破綻・
      MTUの押し出し・レイテンシの内訳と、19命令/バイトの単価の分解
- 常設の関門: CIに「4 機能層 — ネットワーク」。ping先を 10.0.2.2 (netstackが自分で
      答える)、HTTPをジョブ自身のサーバにして**外に出ない**まま、16bitと32bitの
      両方が線に出ることを毎push見張る
- 台帳: virtio-net/virtio-blk は microVM段 (Tier 8、自前カーネルとセット)、
      PAE は x86_64 (Tier 9) で。詳細は ADR-0017

## Tier 6: GUI と音、いろいろなメディアからの起動 (2026-08-13 音声を畳んだ)

**合格判定 = DOOM が音付きで遊べる** (上のマイルストーン4)。機能の列挙ではなく
これで完成を測る — fbdev・PS/2・音・実効速度が全部通らないと DOOM は完成に見えない。
音声は専用Tierにせず、ここに3段の階段で畳む (ユーザー決定):

- [x] **6s: PCスピーカー** — 達成 (2026-08-13)。PIT ch2 のゲート + 0x61 の bit0/1 で、
      coreは `speaker_tone()` が今の周波数を返すだけ、WebAudioを鳴らすのは外側
      (NICと同じ境界の流儀)。ELKSの `echo ^G` が800.3Hz、FreeDOSの `AIR.COM`
      (G線上のアリア) が鳴る。
      **残りの穴**: スライス毎のポーリングなので (1) 1スライス1音で超短音を
      取りこぼす (2) 0x61 bit1 の高速トグルで作る**1bitデジタル音 (PWM)** が原理的に
      出せない。DOOMのPCスピーカー効果音を鳴らすなら、サンプル列を吐く形への
      作り替えが要る
- [ ] **6t: Adlib (OPL2)** — FM音源。ポート0x388/0x389だけで完結 (DMA・IRQ不要)。
      **DOOMの音楽**はこれ。設計の分かれ目が1つ: レジスタだけcoreに持ってJS側 (WebAudio)
      で合成するか、**coreが波形サンプルを吐く**か。FMはエンベロープが時間で進むので
      レジスタの状態だけでは音が決まらない — **後者 (サンプル列を吐く) の方が素直**で、
      下の 6s 作り替えと**同じ境界**にできる
- [ ] **6s+: スピーカーをサンプル生成に作り替える** — 今の `speaker_tone()` は
      スライス毎に「今の周波数」を返すだけなので、**DOOMのPCスピーカー効果音
      (140Hz = 7.1msごとに切り替え) はスライス(~8ms)より速く、取りこぼす**。
      1bitデジタル音 (PWM) も原理的に出せない。サンプル列を吐く形にすれば両方解ける
- 台帳: **Sound Blaster** (DSP + **ISA DMA 8237が未実装** + IRQ5) — DOOMの
      **デジタル**効果音。**「音付きDOOM」にSBは必須ではない** — DOOMは音楽と効果音を
      別々に選べるので、**音楽=Adlib / 効果音=PCスピーカー**でDMA無しに成立する。
      8237という独立装置が要るので、デジタル効果音が欲しくなった時点で取り出す

**音の順番** (2026-08-15 整理): `6t OPL2 (音楽)` → `6s+ スピーカーの作り替え (効果音)`
→ 必要なら `SB (デジタル効果音)`。1段目だけで「音楽が鳴るDOOM」に届く。

- [ ] **6a: フレームバッファ** — **画素の配管は1つ、入口は2つ** (2026-08-15 整理):

      | 入口 | 誰が使うか | 中身 |
      |---|---|---|
      | **VGA mode 13h** | 16bit (FreeDOS・DOOM) | `INT 10h AH=00` でモード13hを受け、0xA0000 の 320×200×8bpp + DACパレット (0x3C8/0x3C9) |
      | **リニアFBの申告** | 32bit (Linux) | zero page の `screen_info` に LFB を申告 → `vesafb` が bind |

      共有するのは dirty検出・wasmの窓・canvas描画で、**16bitと32bitの両方に効く
      唯一の項目**である。
      **「`vesafb` は選べない」は訂正が要る** — 選べない理由は「bzImage直接ロードで
      リアルモードのsetupを飛ばすのでVBEを呼ぶ者が居ない」だったが、それは
      *BIOSを呼んでモードを設定する*話である。`build_zero_page` は既に `screen_info` を
      埋めており (今は「80x25のテキスト」と申告している)、**同じ構造体にLFBの欄がある**。
      我々がfirmware側なのだから、自分で用意したフレームバッファを申告すればよい。
      **要実走確認** (ここは推測なので、6a着手時に必ず実物で確かめる)
- [ ] **6b: PS/2 マウス** — 8042 の第2ポート
- [ ] **6c: ISO起動** — ATA/ATAPI (PIOで読むだけ) + El Torito。
      **ISOの中に埋めたフロッピーイメージをドライブAに見せる**のが El Torito の
      floppy emulation モードで、これなら既存の `INT 13h` 経路がそのまま使える。
      `INT 13h AH=42` (LBA拡張) も足す
- [ ] **6d: HDD** — ATA。**B5 (Web Worker + OPFS) とセット**。理由は下記

**ディスクの効き先** (2026-08-15 整理 — 「ディスクを作れば32bitでも使えるのか」への答え):

| 作る物 | 16bit (DOS/ELKS) | 32bit (Linux) |
|---|---|---|
| **INT 13h の大きいディスク像** | ◎ DOOMを載せる器になる | **✗ 使わない** — 保護モードのLinuxはBIOSを呼ばない |
| **ATA (PIO)** | ◎ (6c/6d) | ◎ ここで初めてLinuxに実ディスクが見える |
| virtio-blk | — | ◎ microVM段 (Tier 8) |

**`Disk` (イメージ + CHS↔LBA変換) は3者の共通の土台**なので、どれから作っても
残りに効く。ただし「INT 13hを大きくする」だけでは32bitには1ミリも効かない。

### GUIの階段 (2026-08-13 追記 — DOOMの先)

DOOM合格後のGUIは、この順に登る (ユーザー方針「ReactOS・軽量GUIを動かしたい」):

- [ ] **6e: Xなしの軽量GUI** — fbdev直描画の世界。`links2 -g`・Nano-X
      (microwindows)・SDL1/fbdev。X要らず = 6a+6bだけで届く最初のGUI
- [ ] **6f: Xfbdev (TinyX/KDrive) + 軽量WM** — twm / fluxbox / IceWM + xterm。
      イメージ候補は **Tiny Core Linux** (FLWM込み~50MB RAM、この用途の定番)
- [ ] **6g: 古典デスクトップ** — LXDE/XFCE級は要実測。**KDE/GNOMEは古典版
      (KDE3・GNOME1〜2世代) のみ視野** — 現代のPlasma/GNOME3+はGLコンポジット
      前提で、グラボを作らない判断 (ADR-0011) と正面衝突するため対象外
- [ ] **6h: ReactOSトレイル** — 速度はPentium 200MHz級 (~150-200 MIPS、JITの
      射程内)。**x87 FPU本体は 4d で実装済み** (2026-08-14、f64裏打ち) なので、
      かつてここに書いていた「隠れた前提」は解けている。
      加えて 6b マウス・6c El Torito・6d ATA・PCI無しHALの実測。
      合格判定:「ReactOSがデスクトップを出す」— DOOMの次の絵になる節目

**FBの設計原則 (6a着手時の約束)**: フレームバッファは**装置の窓ではなく
ただのRAM** — 書き込みフックなし、表示側が毎フレーム全読みして描く
(320×200×8bppで64KB — dirty追跡の賢さは不要)。テキストVRAMのような
書き込みフック式にすると、ゲストのピクセルストアが全部JITの高速路から
弾かれてDOOMの内側ループが死ぬ。

**VGAのplanarモード・CGA/EGA・VBEはやらない** ([ADR-0004](adr/0004-how-far-to-follow-the-bios.md)
の「底が無い」側)。**mode 13h だけは作る** — 2026-08-15の決定で、ここだけは
「0xA0000のリニア320×200×8bpp + DACパレット」と範囲が閉じており、FreeDOS DOOMへの
最短路だからである。以前ここには「mode 13h はやらない」と書いてあり、
マイルストーン節の「FreeDOS DOOMにはmode 13hが要る」と**矛盾していた**。

## Tier 8: マイクロVM化

マイクロVM側の本丸。ハードウェア仮想化 (VT-x/KVM) に頼らないからこそできることで勝負する:

- [x] **8a: 速度の足回り** — TLB は Tier 3c で前倒し済み (4096スロット・旗をbaseの
      下位12bitへ詰めた12バイトのエントリ)。スロット数のスイープも実測済み (D2)
- [ ] **8b: まばらページ割り当て** — 触ったページだけ実メモリを使う。
      512MB×50台が32GBのホストに載る条件
- [ ] **8c: snapshot-fork** — **ブートを1回やって、スナップショットから50台を分岐起動**。
      Firecrackerの高速起動を決定性つきで再現する。KVMには原理的にできない芸
- [ ] **8d: 1台1ホストスレッド** — Machine は自己完結 (グローバル状態なし) なので
      スレッドに1個ずつ配るだけ。**台ごとの決定性はそのまま保たれる**。
      Firecracker も1〜2vCPUのVMを大量に並べる思想で、モデルが一致する
- [ ] **8e: 負荷試験** — 自作ロードバランサ + Locust で 50〜100台に負荷をかけ、
      Linux + rootfs + Python の Hello World コンテナがどこまで捌けるか実測する

**ゲストSMP (1台に複数vCPU) はここではやらない。** LAPIC/IOAPIC・SMPブート・
vCPU間メモリモデルと請求書が長く、32bit時代のワークロードは1CPUで困らない。
現代のユーザーランドがSMPを前提にし始めるのは x86_64 の世界 — Tier 9 側の仕事。
やるときは「vCPU0を64命令→vCPU1を64命令」の**決定的インタリーブ**で、
決定性を守ったままSMPにする (KVMには真似できない芸)。それまでの守りは1つだけ:
**「CPUが1個」という仮定をコードの奥に埋めない** (Cpu は Machine のただの
フィールドであり続ける)。

## Tier 9: x86_64 → 別リポジトリ

このリポジトリでは扱わない。fork して `rustx86_64` として作る。
ロングモード、REXプレフィクスと16本のレジスタ、4段ページング、SSE前提の
ユーザーランド — 積み上げるものが多すぎて、混ぜるとゴールが消える。
ここまでの方法論 (trap駆動開発・lockstep照合・カーネル自身をオラクルにする) が

### B5: Web Worker + OPFS への移行

**HDDをやるならこれとセットになる。**

wasm32の線形メモリは4GBが上限で、エミュレートするRAMとディスクイメージが
同じ4GBを分け合う。1GB程度の仮想HDDなら今のまま載るが、それ以上は無理で、
しかも**リロードで消える**。

OPFS (Origin Private File System) の `createSyncAccessHandle()` は
**`read()` / `write()` が同期API**で、**Web Workerの中でしか使えない**。
これがまさにエミュレータ向けの設計になっている。

```
現在:  メインスレッド ── Emulator ── Vec<u8> (ディスク全部をメモリに)
                                     └ 4GBの天井、リロードで消える

B5後:  Web Worker ──── Emulator ──── OPFS SyncAccessHandle
         │                            └ 同期read/write、永続化する
         └ SharedArrayBuffer で画面とキーをやり取り
```

- ディスクを全部メモリに載せなくてよい → **サイズ上限が消える**
- **書き込みが永続化する** → HDDに書いたものがリロード後も残る
- **計測中にタブが固まる問題も消える** (今はメインスレッドで回している)

ISOとフロッピーは読み取り専用で足りるので、B5を待たずに Tier 6c でやれる。
