# ADR-0005: ローカルで完結するものを先にやる (ネットワークを後ろへ)

- ステータス: 採択 (2026-08-08)
- 影響: [ADR-0002](0002-devices-and-16bit-unix.md) / [ADR-0003](0003-networking-in-the-browser.md) / [ADR-0004](0004-how-far-to-follow-the-bios.md)

## 背景

当初のロードマップは 16bit → **ネットワーク** → 32bit → Linux の順だった。
ネットワークを早い段階に置いたのは「ブラウザの中のOSがどこまでネットワークを
支配できるか知りたい」という動機が出発点だったからである。

Tier 2 (ELKS) を終えた時点で、この順序に2つの問題が見えた。

## 問題1: NE2000 は書いて捨てることが確定していた

ロードマップに自分でこう書いていた。

> **3b: NE2000** — ELKSは virtio-net を知らないので ISA の NE2000 を書く。
> **Tier 5 で virtio-net を書き直すことになる**が、踏み台側は全部使い回せる

つまり **16bitの段階でネットワークをやると、装置を2回書くことが最初から決まっていた**。
ELKS は virtio を知らないので NE2000 が要り、Linux は virtio-mmio で繋ぐのが
遥かに素直なので、NE2000 は Linux に着いた時点で用済みになる。

さらに測定の面でも同じことが起きる。ロードマップにはこうも書いてある。

> TCP over TCP や MTU の本気の測定には Linux のスタックが要るので Tier 5 に回す。
> ELKS の ktcp では L3 の疎通までを取る。

**装置も測定も、どちらも「Linuxに着いてから」の方が良い**と自分で書いていた。

## 問題2: ネットワークだけが外部の用意を要る

他の段は全部**タブの中で完結する**。CPUも装置もBIOSもLinuxも、
落としてきたイメージとブラウザだけで動く。

ネットワークだけが違う。踏み台のEC2インスタンス、ドメイン、TLS証明書、
WSSの終端、TAPとMASQUERADEの設定 — **エミュレータの外側に用意するものが要る**
([ADR-0003](0003-networking-in-the-browser.md))。しかも踏み台は公開しないと
決めているので、成果の見せ方も他の段と違ってくる。

自己完結する仕事と、外部インフラを要する仕事が混ざっていると、
**手が止まる理由が増える**。

## 決定

### ネットワークを Linux の後ろに移す

| 新 | 内容 | 旧 |
|---|---|---|
| Tier 1 | 16bitリアルモードCPU | 1 |
| Tier 2 | 画面とシェル (ELKS) | 2 |
| **Tier 3** | **32bit化** | 4 |
| **Tier 4** | **Linux起動 ← ここで完成** | 5 |
| **Tier 5** | **ネットワーク** | 3 |
| Tier 6 | GUI といろいろなメディアからの起動 | 6 |
| Tier 7 | 64bit (別リポジトリ) | 7 |

原則を一言にするとこうなる。**タブの中で完結するものを先に、
外に出るものを後に。**

### 得られるもの

- **NE2000 を書かなくてよくなる。** virtio-net だけで済む
- **最初から Linux のスタックで測れる。** ELKS の ktcp で L3 だけ見る段が消える
- 32bit化が前に来るので、[ADR-0004](0004-how-far-to-follow-the-bios.md) で
  Tier 4b 待ちにした FreeDOS の続きが早く着手できる
- 完成 (Linux起動) までの道が全部ローカルになり、**外部の用意を待つ場面が無くなる**

### 代償

- **出発点だった動機が後ろに下がる。** 「WASMのLinuxがどこまでNWを支配できるか」は
  この企画のそもそもの問いだった。それを最後に回す判断である
- 番号が変わるので、既に公開した記事の記述と食い違う。
  記事は開発記であって仕様書ではないので、そのままにする

### 捨てるのではなく、後ろに置くだけ

当初この代償を「ELKS がネットワークを喋るところは永久に見られない」と書いたが、
これは誤りだった。**16bit のネットワークは Tier 5 で一緒にやればよい。**

順序を下げたことで、NE2000 の性格が変わっている。

| | 先に書いた場合 | 後で書く場合 |
|---|---|---|
| 踏み台 (EC2/TLS/TAP) | **これも一緒に用意する** | すでに在る |
| virtio-net | まだ無い。NE2000がその場しのぎになる | すでに在る |
| NE2000 の位置づけ | **置き換えられる中間物 (捨て仕事)** | **16bitマシン用の増設** |

問題は「NE2000 が無駄」ではなく「**先に書くと無駄**」だった。
高い部分 (外部インフラ) を済ませた後なら、足すのは装置モデルだけで済み、
しかも既に別の答え (virtio-net) があるので置き換えられる心配も無い。

これは [箱 B1 のマシンプロファイル](../roadmap.md)
とも噛み合う。**16bitマシンは NE2000、32bitマシンは virtio-net** という
構成の違いが、そのままプロファイルの差として表現できる。

## 検討した代替案

**番号を変えずに実行順だけ入れ替える。** ADR 4本と公開済みの記事が番号を
参照しているので、番号を動かさない案も考えた。だが「Tier 4 を Tier 3 より先にやる」
という状態が恒久的に残るのは、教材として読みにくい。**リポジトリの中の一貫性を優先**し、
番号を振り直して参照側を直した。

**ネットワークを完全にやめる。** 踏み台が要る以上、これも選択肢ではあった。
だが [ADR-0003](0003-networking-in-the-browser.md) の問い
(ブラウザのOSはどこまでネットワークを支配できるか) は、この企画で
一番知りたかったことである。**順序を下げるだけで、やめはしない。**
