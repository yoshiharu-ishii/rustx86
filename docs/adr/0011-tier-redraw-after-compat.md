# ADR-0011: 互換達成後のTier引き直し — JIT完走を前倒し、バスは作らない

日付: 2026-08-12
状態: 採用
関連: [ADR-0005](0005-local-first-roadmap.md) (ローカル優先の順序)、
[ADR-0007](0007-cpu-optimization-steps.md) (最適化の運転方針)、
[ADR-0008](0008-template-jit.md) (JITロードマップ)、
[ADR-0010](0010-test386-full-compat.md) (互換完璧化)

## 何が変わったか

test386.asm が完全合格した (POST FF + EE 44926行一致、PR #78)。
互換は CI の常設門番 (cosim・CPU互換・3OS回帰・JIT決定性) になり、
**「意味論を壊したら即座に赤くなる」網が張られた**。

この網こそ、凍結していたJITを再開する条件だった — JITの怖さは
「速い写しが原本と食い違うこと」で、食い違いを検出する審判が
薄いうちは進められなかった。互換の完成は最適化の再開条件である。

## 決定

### 1. 着手順: JIT完走 → グラフィック → ネットワーク

```
  いま                     次                 その次           その先
┌──────────────┐   ┌──────────────┐   ┌─────────────┐   ┌────────────┐
│ 互換ピラミッド │ → │ F1c JIT完走   │ → │ Tier 6      │ → │ Tier 5     │
│ L1 全緑 ✅    │   │ (Cranelift)   │   │ グラフィック │   │ ネットワーク │
│ CI門番常設    │   │ 北極星185MIPS │   │ FB→DOOM     │   │ wsslirp+    │
└──────────────┘   └──────────────┘   └─────────────┘   │ virtio-net  │
                                                         └────────────┘
```

- **F1c (Cranelift JIT) を Tier 7 から前倒しして着手する。**
  マイルストーン1 (100 MIPS) の実行であり、ゴールは北極星
  (v86実測 160〜185 MIPS、docs/reference/perf.md) に並ぶこと。
  ネイティブ先行 — 終点はmicroVM (Tier 8) であり、wasm特有の
  職人仕事は載らないという凍結判断 (2026-08-11) はそのまま。
  F1a/F1bで作ったフロントエンド (フォールト脱出モデル・語彙・
  カバレッジ機構・interp/JIT並走の審判) は全部持ち上がる
- **グラフィック (Tier 6) はその後。** 合格判定は変わらず VGA DOOM
- **ネットワーク (Tier 5) はさらに後。** 踏み台 (EC2/TLS) の用意が
  要る「タブの外に出る」仕事を最後に置く原則 (ADR-0005) は不変。
  網元は wsslirp (Go、別リポジトリ) — 単体で先に検証できる

Tierの**番号は変えない** (5=NW, 6=GUI, 7=ネイティブ)。番号は「何が
動くか」の深さの名前であって着手順ではない — 順序はこのADRが持つ。

### 2. バスとカードは「作らない」を明文化する

質問「PCIとISAも実装してNWカードとグラボも実装しないとダメ?」への答え:

| 部品 | 判断 | 理由 |
|---|---|---|
| **PCIバス** | **作らない** | virtio は **virtio-mmio** で載せる (カーネル引数 `virtio_mmio.device=` で番地を教える)。Firecracker自体がx86でMMIOトランスポートを選びPCIを持たない — 終点 (Tier 8) と同じ形にする。既定路線 (Tier 4c の註) の再確認 |
| **ISAバス** | **既に在る (作るものが無い)** | ISAの正体は「ポートI/O + IRQ (+DMA)」で、PIT/PIC/UART/8042として実装済み。バスとしての列挙機構は無い。ISA DMA (8237) はFDD/SoundBlaster用で、使う装置を積む予定が無い |
| **NWカード** | **virtio-net 1枚** | Linux側はこれだけ。ELKS用のNE2000 (ただのポートI/O装置) は踏み台とvirtio-netが揃った後の5eのまま (ADR-0005の順序) |
| **グラボ** | **作らない** | 必要なのはGPUではなく**線形フレームバッファ + fbdev** (Tier 6a)。ブートローダが screen_info を直接埋めて simplefb 相当で見せる — VGAのplanarモードやmode 13hはやらない (ADR-0004の「底が無い」側)。3Dも2Dアクセラレーションも無し |

### 3. 台帳に寝かせるもの (棄却ではない)

- **最小PCI**: 「無改造のディストロカーネルで動くこと」が要件に
  なったら再訪 (virtio-pci しか探さないカーネル・bochs-drm が対象)。
  ホストブリッジ+コンフィグ空間だけなら数百行の見積り
- **Alpine lts カーネルの CONFIG_VIRTIO_MMIO 有無は要実測** (Tier 4c
  着手時の最初の確認)。無ければ選択肢は (a) 自前カーネルconfig
  (vmlinux抽出は既にやっている)、(b) 最小PCI前倒し — 実測してから選ぶ
- **wasm JITの凍結解除**: Craneliftの数字が出た後、フロントエンド
  共通化の載せ替えコストと合わせて再判断

## 理由の芯

1. **速さは検証の単価** (2026-08-10のユーザー方針) — この先の
   グラフィック・ネットワーク・microVMの検証は全部実行速度の上に載る。
   互換の網が張れた今が、単価を下げる投資の最適点
2. **終点から逆算して部品を選ぶ** — Firecrackerに無いもの (PCI、
   VGAモード、本物のGPU) は途中でも作らない。互換の対象はCPUで
   あって、周辺機器のレトロ再現ではない (ADR-0004と同じ線引き)
3. **順序は変えるが約束は変えない** — DOOM合格判定、NW最後 (ADR-0005)、
   PGOはFirecracker段の道具 (ADR-0009)、はすべて維持
