# ADR-0007: CPU最適化はデコード済み命令キャッシュを本丸に、段階を刻む

- ステータス: 採択 (2026-08-10)
- 関連: [docs/perf.md](../perf.md) (数字と進捗の生きた台帳) /
  [ADR-0001](0001-16bit-cpu-and-cosim.md) (cosimが検証の土台)

## 背景

フルブートの目標は10秒 (Tier 3e)。GUI (Tier 6) は起動が遅いと使い物に
ならず、マイクロVM (Tier 8) の50台並行でも1台の速さが分母になる。

現在地は M1 ネイティブで **~30 MIPS = 1命令およそ110サイクル**。
プロファイルの上位は step 33% (フェッチ+プレフィクス+巨大matchの
ディスパッチ)、modrm 13%、memmove 12%、translate 8%。

実行量そのものを減らす手 (P0) は打ち終えた — HLT早送り、vmlinux直接
ロード (解凍ステブ540M命令の削除)、条件付きCPU控え、スナップショット起動。
残るは**実行そのものの速さ**であり、それがこのADRの主題である。

## 30 MIPS の正体 — コードではなく構造

毎命令「フェッチ → プレフィクスループ → 巨大match (間接分岐) →
ModRM再デコード → 実行 → 帳簿」を踏む古典的スイッチ型インタプリタの
相場が数十MIPSである。支配項は**間接分岐の予測ミス**と毎命令の再デコードで、
これはメモリ経路をいくら磨いても動かない。

実測でもそれを確認した (交互A/B、詳細は perf.md):

- 命令フェッチ窓 (1命令1回の変換に集約) → **差がノイズに沈み、捨てた**
- プロファイル27%を占めた観測用BTreeSetの削除 → **壁時計は不変**
  (ストールの付け替え先だった。「倒れた場所は犯行現場ではない」)

## 検討した選択肢

### 案A: メモリ経路の微修正を積み重ねる — 棄却

上記の通り2案を実測して棄却。TLBヒットは既に十分安く、
ここに構造の上限を破る余地は無い。

### 案B: テンプレートJIT (wasm/ネイティブコード生成) — 後回し

最速だが、(1) **決定性 (ビット同一再実行) を壊さない設計が難しい**、
(2) wasmとネイティブで生成系を二重に持つことになる、(3) デバッガ・
スナップショットとの整合が複雑になる。デコードキャッシュで100 MIPS圏に
届くなら要らない。届かなかったときの研究枠として残す (perf.md P4)。

### 案C: デコード済み命令キャッシュ — 採択

同じ命令を何百万回もデコードし直すのをやめる。実CPUのuopキャッシュ、
QEMU TCG のTB、と同じ系譜の答えで、インタプリタのまま構造の上限を破る。

- 物理アドレスをキーに、デコード結果 (プレフィクス・オペコード・
  オペランド・命令長) を控える
- 2回目からはデコードを飛ばし、デコード済み列を順に実行する。
  ディスパッチの間接分岐が「毎回ランダム」から「列に沿って予測可能」になる
- **無効化は書き込みでページ単位** — TLB・VRAM検出と同じ発想。
  自己書き換え (DOSは平気でやる) はこれで正しく落ちる

## 決定: 段階を刻む (一気に全命令をやらない)

x86の全命令を一度にIR化するのは事故のもとである。**フォールバックを
残したまま、頻出族から刻む**:

1. **P1a**: IRと実行器を頻出族だけ (mov / ALU / jcc / push / pop / inc / dec /
   test / cmp / lea / shift)。キャッシュミス・未対応命令・例外的状況は
   従来の `cpu::step` にそのまま落とす
2. **P1b以降**: カバレッジを実測 (ブート中のフォールバック率) で見ながら広げる。
   率が1%を切ったあたりで頭打ちのはず
3. **P2**: デコード済み列の上での質の改善 — フラグの遅延評価、頻出ペアの融合、
   RMWの変換1回化 (perf.md)

### 気をつける罠 (先に書いておく)

- 自己書き換え: ページ無効化で受ける。**書き込み経路に入れる1判定が
  16bit機の全域に乗る**ので、コストは交互A/Bで測ってから採る
- REP系: 1命令が何ステップにも割れる。IR化は後回しにしてフォールバックでよい
- デバッガ (`dbg.before_exec`)・トレース: デバッガONのときはキャッシュを
  使わない、から始めてよい (見張っていなければ真偽値1つ、の原則を守る)
- スナップショット復元・`load_state`: キャッシュ全破棄 (TLBと同じ扱い)
- #PF巻き戻し: 実行器はフォールバック側と同じ「控えて巻き戻す」規約に従う

## 検証 — この網があるから内側を触れる

- **決定的命令数**: OS起動回帰の到達命令数 (Linux 580M) が**1つも変わらない**
  こと。最適化が意味を変えていないことの証明器
- cosim (単発の意味論) / kernel_lockstep (実カーネルを1命令ずつ突き合わせ)
- 壁時計は交互A/B (`bootphase`) 以外を信用しない (M1は熱ダレする)
