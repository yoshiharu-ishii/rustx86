# ADR-0006: セグメントの隠しレジスタを実機と同じ構造で持つ

- ステータス: 採択 (2026-08-09)
- 影響: Tier 3a 全体。[ADR-0001](0001-16bit-cpu-and-cosim.md) の「レジスタは最初からu32」と同系の judgment

## 背景

プロテクトモード (Tier 3a) に入るにあたり、コアには8086の前提が1つ
焼き込まれていた。

```rust
pub fn linear(seg: u16, off: u16) -> u32 {
    ((seg as u32) << 4).wrapping_add(off as u32) & 0xF_FFFF
}
```

この自由関数の型は「**セレクタの値だけから番地が決まる**」と言っている。
リアルモードではそのとおりで、27箇所がこの関数で番地を作っていた。

プロテクトモードはこの前提を壊す。セレクタはもう番地の材料ではなく
**GDTの行番号**であり、番地の材料はロード時に記述子から取り出した
base/limit/属性である。

## 選択肢

### A. モードで分岐する変換関数

`if pe { gdt_lookup(seg) + off } else { seg<<4 + off }` を変換のたびに行う。

- 実装は最小
- **毎アクセスでGDTをメモリから読むことになり、意味論も間違う** —
  実機はロード時に写しを取るので、GDTを後から書き換えても反映されない。
  この差はOSが実際に踏む (Linuxはセグメント切り替えの周辺でGDTを書き換える)

### B. 隠しレジスタ (実機と同じ構造)

セグメントレジスタを「見える部分 (セレクタ)」と「隠し部分 (base/limit/
access/Dビット)」に分け、**ロード命令だけ**がGDTを読んで隠し部分へ写す。
以後のアクセスは写しだけを見る。

- 実機 (386) がやっていることそのもの。意味論が定義から一致する
- リアルモードは「写しに常に sel×16 が入っている」**特殊ケース**になり、
  両モードが1本の経路に統一される
- 教材としても、「プロテクトモードの正体は隠しレジスタ」という
  実機の核心がコードの構造にそのまま現れる

## 決定: B。ただし写しは遅延評価にする

構造はBを採るが、1点だけ実機と変えた。**リアルモードでは写しを読まず、
`seg_base()` が毎回 sel×16 を計算する**。

```rust
pub fn seg_base(&self, i: usize) -> u32 {
    if self.pe() { self.hidden[i].base } else { (self.sregs[i] as u32) << 4 }
}
```

理由は既存コードとの契約である。テストや周辺コードは
`m.cpu.sregs[CS] = 0x1234` と**セレクタへ直接書く**。実機どおり
「ロード時に写す」を貫くと、この直接書き込みが写しを腐らせて嘘になる。
遅延評価なら、リアルモードにおいてセレクタが唯一の真実であり続ける。

代償として、PE が 0→1 になる瞬間に写しを実体化する必要がある
(実機ではこの瞬間も写しを見続けているので何も起きない場面)。
`MOV CR0` のPE遷移でのみ6本を `sel×16` で初期化する。

境界が1命令ぶんだけ実機と同じ2段構えになるのは、むしろ好都合だった:
PE=1 の直後・far jump の前は「モードは保護、実行はまだ16bit」という
実機の姿がそのまま再現される。

## 代償と記録

- **スナップショット形式がv2になった。** 隠しレジスタは機械の状態そのもの
  (セレクタ 0x08 から base=0 は再構成できない — GDTは書き換わっているかも
  しれない) なので保存対象。v1は「形式の版が違う」と断られる
- リアルモードの1MB折り返し (`& 0xF_FFFF`) は `lin()` の中へ移り、
  保護モードでは折り返さない。**ただしメモリ自体がまだ1MBなので、
  1MB超のアドレスは read8 側で折り返る** — A20とメモリ拡張はページング
  (3c) と同時に扱う
- 特権チェック (DPL/RPL/CPL) はまだ実装していない。リング0だけの世界では
  恒真になるため。**ただしチェックすべき材料 (accessバイト) は写してある**
  ので、リング3を作るときに材料集めからやり直すことはない

## 検証

- 全メモリアクセス経路 (27箇所) を書き換えた回帰: 98テスト全通過、
  FreeDOS が `dir` まで、ELKS が tetris まで到達。ELKSは改修前と
  **ビットまで同じ 45,669,277 命令** — リアルモードの挙動はゼロ変化
- CPU照合 (Unicorn、毎命令比較) 一致
- 遷移の2段構え・記述子ロード・スナップショット往復をテストで固定
  ([core/tests/protected.rs](../../core/tests/protected.rs))
