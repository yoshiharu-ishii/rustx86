# ADR-0015: CPU最適化フェーズの終了 — 判別則4条と「理論ラウンドの門」

- 状態: **決定** (2026-08-13 ユーザー決定、外部レビュー往復の裁定を採用)
- 日付: 2026-08-13
- 関連: [ADR-0007](0007-cpu-optimization-steps.md) (出口条件 — 通過済み)、
  [ADR-0013](0013-f1c-freeze.md) (JIT削除)、[ADR-0014](0014-external-review-hotpath.md)
  (外部レビューの裁き方)、[perf-log.md](../reference/perf-log.md) (全実測)

## 決定

1. **CPU性能最適化フェーズをここで終了する。** 出口条件 (フルブート10秒 /
   ~100 MIPS、ADR-0007) は通過済み — 公式 9.7s×2、ベスト9.5s (102 MIPS)、
   定常9.3〜9.4s (**104 MIPS**)。13 MIPSから8倍
2. **次はTier 6 (GUIの階段)**: 6a線形フレームバッファ → 6b PS/2マウス →
   fbdev直描画 → TinyX → …。合格判定は「**DOOMが遊べる**」— 104 MIPSを
   ベンチ数字からユーザー価値に変換する段階
3. **host MMU shadow mapping はTier 8の枠で保全**: アドレス変換の主体を
   ホストMMUへ移す案 (判別則1〜4の外へ土俵を移せる唯一の案) だが大工事。
   microVM多数台で「1台あたりのCPUコストが支配的」という要求が出て
   初めてROIが成立する
4. **追加のCPU最適化案は「理論ラウンドの門」を通す** — コードを書く前に
   2問に答えられない案は実装しない:
   - その案は**判別則(4)をどう破るのか?**
   - **次反復開始までのexposed dependencyを何サイクル削るのか?**

## 判別則 (最終形、実測26本で確立)

1. **独立な帳簿はOoOの影** — 削っても無駄 (hits計数・境界検査・再デコード)
2. **次の値を作る直列仕事は削れば効く** — B4 -43% / 受け口の税 -22% /
   batch1 -8% / translate-first -5%
3. **並列な枝は何本減らしても最長の1本分** — 世代照合のイベント駆動化がワッシュ
4. **命令内で閉じる依存鎖を短くしても、そのレイテンシが隣接ゲスト命令との
   OoO重畳に隠れているなら壁時計は動かない。狙うべきは次反復の開始を阻害する
   exposed dependency** — PC-lookahead (+2%、理論上はTLBロードを鎖から
   追放できていた) とbatch1の勝敗を分けた法則。命令内の鎖でもROB詰まりや
   load-after-storeで次命令へ波及すれば律速に戻り得る (970Mブートでは未観測)

## 根拠 — 反証実験は足りている

ワッシュ・負けの墓標: SLOTS増 / SoA / ページ跨ぎ連結 (chain 69→20万命令
にしてなお) / 16bit語彙 / dTLB二段 / HotState / 世代照合削減 /
PC-lookahead (依存鎖を実際に1段削ってなお+2%) / B3・B5系の連結高度化
(悪化実績)。これは「まだ思いついていない5%がありそう」な状態ではなく、
**インタプリタという実装方式に対して十分な反証実験を済ませた**状態である。

## 教訓

前回レビューは「TLBロードをcritical pathから追放できる」と主張し、実際に
追放できた。**それでも速くならなかった**。そこから「依存鎖なら何でもよい
わけではない — 反復間に露出している依存鎖でなければならない」という一段
深い法則が出た。最適化として負け、マイクロアーキテクチャの理解として大勝ち。
